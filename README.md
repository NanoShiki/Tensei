# Tensei

使用 Godot 开发，支持在 macOS 和 Windows 上通过同一个 GitHub 仓库协作。

## 开始开发

1. 两端安装相同版本的 Godot。当前 `project.godot` 标记为 4.7；请保持具体补丁版本或开发构建一致。
2. 克隆仓库：`git clone https://github.com/NanoShiki/Tensei.git`。
3. 在 Godot 项目管理器中导入 `project.godot`，等待资源导入完成。

项目为日式西幻题材的多人地下城回合制战斗冒险游戏，局内采用横版回合制战斗。当前主菜单提供「开始旅程」、多角色多记录读取与可配置「战斗演练」入口。新角色在城市准备、接委托，从第一层出发，沿节点下潜和自由返程，回城交付、升级、打造、选择基础职业、加入晨行眷族并编队、转会炉心／集市、配装武器／护甲并再出发；战斗每人每回合默认行动一次，技能和药水选中后点选目标，阶段目标见 [项目管理与开发计划](Docs/游戏整体/项目管理与开发计划.md)。

设计与开发说明从 [项目文档树与阅读入口](Docs/文档导航.md)开始，按全局方向、模块规则、实现说明与素材记录逐层查阅，参与记录见 [项目贡献者](Docs/项目规范/项目贡献者.md)。

## 协作约定

- 代码、资源和文档变更均优先通过 Pull Request（PR）开发和合并，尽量避免直接向 `main` 推送变更。
- 开始开发前同步最新的 `main`，创建独立工作分支；完成修改、提交和验证后，推送工作分支并创建 PR。推送工作分支以创建或更新 PR 属于正常流程。
- PR 标题统一采用 `关键词：中文描述` 格式，使用英文关键词和中文冒号，例如 `docs：明确pr开发流程`、`fix：修复ui bug`。常用关键词包括 `docs`（文档）、`fix`（修复）、`feat`（新功能）、`refactor`（重构）、`test`（测试）、`chore`（维护）。
- PR 描述以中文为主，应说明变更目的、主要内容及验证情况；技术术语、代码标识符、命令和文件路径可保留原文。
- 开发者及 AI 代理均应遵循 [AGENT.md](AGENT.md) 中的开发准则。
- 多人开发时尽量避免同时编辑同一个场景。
- 提交场景、脚本、资源及对应的 `.uid` 和 `.import` 文件；`.godot/` 是本机生成的缓存，不提交到仓库。提交范围与 `.uid` 处理方式见 [版本控制与文件提交](Docs/项目规范/版本控制与文件提交.md)。
- 使用 `res://` 和 `user://` 路径，避免写死操作系统绝对路径。
- 文件名与引用的大小写保持一致；文本换行由 `.gitattributes` 统一为 LF。
- 平台相关功能及渲染效果需要分别在 macOS 和 Windows 上验证。

## 回归检查

使用与项目一致的 Godot 控制台构建和 Python，在仓库根目录执行：

```powershell
python Tools/run_demo_checks.py --godot "D:/Godot/godot/bin/godot.windows.editor.x86_64.console.exe"
```

其他环境把 `--godot` 改为实际引擎路径，也可设置 `GODOT_BIN`。默认导入资源、运行全部 Godot 专项、个人存档、角色库与共享成长的独立进程写／读和 Python 工具测试；`--tests test_city_loop test_quests_growth` 可选单项。每组有超时、退出码、完成标记和引擎错误检查，终端打印 PASS／FAIL 与临时证据目录；查看 `summary.json` 和对应 `console.txt`、`engine.log`、事件 JSONL。部分错误注入专项的业务 ERROR 为预期，不自动计入日志规则；正常流程专项单独校验业务不变量。详细范围见 [运行日志与诊断](Docs/项目规范/运行日志与诊断.md)。画面与操作体验继续在 Godot 按 F5 验收。

## 当前 Demo 验收入口

Godot 导入本项目后按 F5。主菜单右上“试玩指南”或 F1 查看八段流程；独立演练在“开始旅程”→“战斗演练配置”，适合先试职业、装备、三人和双敌。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 演练配装 | 法师、2级、淬火铁剑、铁甲、双敌、3人、第4层、种子7 | 三己方两敌方；洛恩 AC13、敌人 HP29/25；选飞弹再点第二敌人只伤该目标 |
| 同种子重开 | 演练GM秒杀后“再试一次” | 保留配置及相同先攻；原个人记录与组织成长不变 |
| 护甲与职业 | 城市用6金币3铁片打造铁甲，下滚切布衣／铁甲，再切法师 | 武器独立保留；护甲 AC+1，剑士15、法师13；切装备不扣钱或恢复生命 |
| 组织服务 | 炉心会员持有铁剑后造淬火剑；集市供货2铁片→5金币，入会后会员礼包6金币→3药水 | 各服务贡献只归服务方，同角色同配方／订单只计一次；转会保留成品 |
| 批量交易 | 数量改为3，买治疗或卖3铁片 | 治疗扣9金币得3瓶；出售得3金币扣3片；库存不足无部分结算 |
| 第五层补给 | 第五层入口点击休整站 | 8金币恢复存活成员各至多12；不复活、不推进刷新，途中药水更贵 |
| 双敌与暂停 | 第四层首节点战斗，点暂停后等待再继续 | 两名敌人分别行动，全清才胜利；暂停冻结动作、动画和随机进度 |
| 原地手动保存 | 城市／地图保存A并继续，再保存B；覆盖A先取消再确认 | 同角色保留多个时点；继续留原位置且计时不变，覆盖仅改所选记录 |
| 回城后接着探索 | 地图切返回沿合法分支回城补给，再出发／切深入 | 合法路线自由选择，到访标记保留当前远征；刷新只按实际移动减少 |

完整试玩仍以六段主成长流程到第五层和等级5为目标；30层为演示模板，价格、难度与正式素材待用户体验反馈。技术检查和用户认可分别记录于 [开发计划](Docs/游戏整体/项目管理与开发计划.md)。GM测试改动会进入正式旅程的手动存档。

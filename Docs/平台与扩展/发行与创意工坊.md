# 发行与创意工坊

状态：设计草案，待实现。目标上线 Steam，联机基于 Steam，并支持 Steam 创意工坊。当前尚未接入 Steamworks、发布构建或实现扩展加载；具体插件、内容范围与发行时间待确认。

## 平台体验

玩家通过 Steam 获取游戏，选择自己的角色存档进行单人或联机冒险，并通过创意工坊获取社区内容。工坊的浏览、订阅、下载、启用和更新提示需纳入产品流程；创作者的打包、验证和发布流程也需规划。

Steam 提供大厅与匹配能力，网络通信通过相应网络接口接入；本项目继续采用玩家主机承担游戏权威的 Listen Server。候选接入方式为 Steam 大厅配合 Steam Networking，具体 Godot 集成工具及 SDK 版本待验证。[大厅文档](https://partner.steamgames.com/doc/features/multiplayer/matchmaking)、[网络文档](https://partner.steamgames.com/doc/features/multiplayer/networking)。

创意工坊提供内容发布与订阅分发接口，游戏需要实现对应的内容格式、加载和玩法接入。Steamworks 的 ISteamUGC 是相关接口依据。[创意工坊实现指南](https://partner.steamgames.com/doc/features/workshop/implementation)。

## 实现前需要预留的边界

以下为架构建议，落实前需结合首个可玩原型验证：

- 平台适配层负责 Steam 身份、房间、邀请、连接和工坊服务，游戏规则通过明确接口调用；保留本地开发与测试入口。
- 内容注册层用稳定且带命名空间的标识组织物品、职业、技能、角色部件、动画、地图、首领和随机效果；存档及网络协议引用内容标识与版本。
- 扩展清单描述扩展标识、版本、依赖、游戏兼容范围和资源入口，区分 Steam 工坊条目标识与游戏内部内容标识。
- 加载前检查依赖、冲突、格式和资源引用，并明确加载顺序。版本变化和缺失内容需给出可操作提示，避免静默破坏角色存档。
- 联机入房时核对影响玩法的内容集合与版本；纯表现内容的差异许可待分类设计。会话期间建议固定内容版本，更新在退出会话后处理。
- 明确数据资源与脚本扩展的开放边界；任意脚本执行能力需要单独设计加载权限与隔离策略。

## 创意工坊内容候选

| 候选类型 | 接入关注点 |
| --- | --- |
| 外观部件与武器外观 | 身体模板、方向、挂点、动作和渲染兼容 |
| 武器、技能、职业或随机效果 | 数值规则、触发条件、存档引用与联机一致性 |
| 地图、首领与终局遭遇 | 地图连接、生成条件、缩放规则和奖励归属 |

以上仅为扩展候选，首发支持的类型、是否提供编辑器和脚本模组仍待确认。模组对角色成长、官方内容平衡和成就的影响，需要确定独立存档、内容标记或准入策略。

## 后续验收与待确认

接入阶段需验证 Steam 初始化和失败提示、身份与大厅邀请、主机连接与退出、内容发布订阅及下载完成、依赖缺失、版本不一致和更新后的存档兼容。具体测试依赖有效的 Steamworks 应用配置与选定集成工具。

待确认：发行平台覆盖范围、Steam App ID 与构建配置、SDK 和 Godot 插件选型、首发工坊内容类型及制作工具、内容冲突策略、单人离线范围，以及 Steam 云存档、成就和 Steam Deck 等可选功能。上线与工坊支持为目标，发布日期与上线操作另行安排。

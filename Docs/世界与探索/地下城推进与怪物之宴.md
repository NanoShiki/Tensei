# 地下城推进与怪物之宴

状态：下潜地图、历史楼层、自由选择向上路线的返程、按移动步数刷怪及单次回城摘要已实现。避战、正式城市、永久收益和存档仍待实现。当前规则优先服务完整 Demo，数值随试玩调整。

## 已确定方向与地图结构

每次远征从第一层出发，每层包含入口、三步分支和出口。下潜沿连线向下一步移动；返程沿连线反向向上，可以选择下潜时没有经过的分支。历史路线用于记录经历，不限制返程选路。当前不允许跳过节点或返程中转为下潜。

返程从本层入口回到上一层出口，再自由选择该层的上行分支；第一层入口连接城市。战斗未结算时不能移动、切换返程或回城；失败终止本趟。

## 按步数刷新

用户确定：每成功走一步，怪物刷新倒计时减少一个单位。现实时间流逝、停留、查看界面、切换返程、战斗回合与战斗结算均不推进计时。

当前 Demo 的计步边界：一次合法的节点移动、跨层返回或回城各算一步。下潜点击出口并自动抵达下一层入口合为一次移动；生成地图本身不额外计步。非法选择、重复提交、战斗锁定期间的移动请求均不计步。

- 初始战斗节点有怪物；战胜后开始倒计时。Demo 暂用 3–5 步，按种子、楼层、节点和清理次数确定，供试玩调整。
- 每步先更新全部已生成楼层的倒计时，再检查目的地。目标原本剩 1 步时，进入就会刷新并触发战斗，按钮悬停明确提示这一边界。
- 倒计时到 0 后怪物保持在场，不继续扣成负数或重复刷新。再次战胜后开始新一轮倒计时。
- 所有楼层共用移动步数，离开当前层也继续推进历史层倒计时。预览、读取快照不消耗随机数或重新抽取阈值。
- 地图显示剩余步数、怪物是否在场及刷新进度条。当前采用文字与进度条反馈，底部向上恢复角色图标颜色留待美术表现迭代。

返程时，未走过的战斗分支和已经刷新的节点均正常触发战斗，胜利后继续返程；未刷新的清理节点直接通行。当前刷新仍使用哥布林，更多编队和避战待接入。

## 节点与奖励

`floor_run.gd` 默认 30 层，可配置；每层 8 节点，同一拓扑模板按种子变化部分类型。30 为演示参数，尚无 30 套独立主题。第一步必为战斗，第二步至少一条营地路线。

| 节点 | 行为 |
| --- | --- |
| 战斗 | 有怪物时进入战斗；清理后等待移动步数刷新 |
| 营地 | 首次进入恢复 10 HP，受上限限制；返程首次进入也可领取，重复经过不再恢复 |
| 补给 | 首次进入获得 1 瓶治疗药水，重复经过不再发放 |
| 出口 | 下潜进入下一层，最深层停止下潜并可返程；返程时可选择连入出口的任一上行分支 |

刷新只改变战斗遭遇，不重置营地、补给、唯一奖励或任务领取。当前战斗无物品奖励。正式掉落、首领、宝箱与任务需各自维护领取边界。

## 运行时状态与结算

| 状态 | 当前职责 |
| --- | --- |
| `run_id`、节点 `key` | 每次出发独立身份；key 由远征 ID、楼层与局部节点 ID 组成 |
| `route`、`return_route` | 分别保留下潜和返程经过的完整节点 key，待结算战斗胜利后才加入 |
| `visited`、`cleared`、`done` | 到访、曾清理、下潜节点完成分别记录，刷新不擦除历史 |
| `enemy_active` | 当前怪物是否在场，与历史清理状态独立 |
| `respawn_in`、`respawn_total`、`clear_count` | 剩余刷新步数、本轮总步数、清理次数 |
| `steps_taken`、`battles_won` | 本趟合法移动次数、累计战斗胜利次数（包含刷新后战斗） |
| `phase`、`pending` | 下潜／返程／回城／失败阶段，以及当前待结算战斗 |

`return_targets()` 列出全部合法返程目的地；仅剩一个目标时 `return_target()` 为快捷按钮提供目标。`step_return(expected_key)` 校验目标后计步、移动或进入遭遇。战斗胜利后回写位置，保留返程阶段。

`floor_snapshot()` 和 `return_summary()` 返回深拷贝。第一层入口回城只生成一次“平安归来”摘要，展示最深层数、累计胜利次数、生命与两类药水。回城后不能继续移动；地图的“放弃并回主菜单”不生成成功摘要。所有数据仅驻内存，重新出发清空旧状态。

## 后续内容

完整 Demo 优先补城市准备、背包、掉落、成长、打造、保存和阶段首领，再依据试玩打磨刷新间隔、避战代价、地图密度和图标表现。避战需先显示资源代价及后果，无法支付时保留交战。具体公式与编队强度可用临时可调数值推进。

怪物之宴仍是有预兆的高风险多波事件，成功后获得素材与补给，当前未实现。普通节点刷新不能随机转成未告知的强制多波战斗。安全楼层、联机路线选择及长期失败损失后续单独设计。

## 手动验收

使用当前分支，Godot 4.7.2 按 F5 → 开始旅程 → 逐层探索。

1. 完成首场战斗，记录该节点的“刷新还需 X 步”。停留或查看地图后数字不变；走到第二步营地后应恰好减少 1。
2. 在营地点“开始返程”。第一步两条战斗分支都应高亮；可选择下潜没有走过的那条，并正常触发战斗。胜利后仍处于返程，可继续到入口。
3. 另一趟多走几步再返程：倒计时每次移动减少 1，到 0 显示“怪物在场”。进入已刷新节点重新战斗；胜利后重新显示 3–5 步。
4. 当目标剩 1 步时悬停查看提示，进入应遇敌；已领取的营地与补给再次经过不发放，未领取的分支可首次领取。
5. 抵达第二层后返程，应回到第一层原地图并可重选分支；第一层入口回城显示准确摘要，缩小到 960×540 后按钮和状态应完整可读。

自动化覆盖非法移动不计步、跨层同步倒计时、归零边界、重复结算、返程遭遇、摘要隔离与重开。用户确认选路清晰度和刷新压力；避战、存档、正式城市及永久收益不在本轮验收范围。

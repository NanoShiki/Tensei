# 地下城推进与怪物之宴

状态：每层一张独立分支地图、每趟从第一层出发、返程途中怪物会随机刷新且可交战或避战，为用户确定方向。轻量下潜地图、历史路线、原路返程和单次回城摘要已实现；刷新、避战和永久收益尚待实现。返程骨架按本页短切片规则验证。

## 地图结构

参考《杀戮尖塔》的节点与分叉连线表达。一个地下城楼层包含完整的小地图：入口 → 多步分支节点 → 出口。完成当前层的出口后才生成下一层地图。节点步数与地下城层数分别计数。

每层展示本层节点类型、连线、当前位置与已完成节点。下潜时只可进入当前位置直接相连的下一节点；返程时沿本趟实际通过的节点逆序返回。不能跳节点、改走未选分支、重复领奖或在战斗中切换路线。

## Demo 范围与配置

`Scripts/Exploration/floor_run.gd` 提供地图数据，`total_floors` 默认 30，可配置。30 层仅为“几十层”的演示参数。每层 8 个节点：1 入口、3 步各 2 个分支、1 出口。同一模板复用，各层按种子决定部分节点类型，尚未制作 30 套独立主题或关卡内容。

| 节点 | 已实现行为 |
| --- | --- |
| 战斗 | 进入洛恩对哥布林场景，胜利后完成该节点 |
| 营地 | 恢复 10 HP，受到生命上限限制 |
| 补给 | 获得 1 瓶治疗药水 |
| 出口 | 保留生命和药水，进入下一层；最后一层停止下潜，提示开始返程 |

第一步必为战斗，第二步至少有一个营地可选，其他节点由种子选择。为保证小规模演示可达，各分支连到下一步两个节点；生成更复杂拓扑、减少交叉线与不同区域主题属于后续工作。

节点奖励只结算一次；战斗失败结束本次探索。当前探索状态只在内存中，返回主菜单后重新开始会创建新旅程。原路返程与回城摘要已实现；城市场景、永久收益、存档与读档待实现。

## 当前远征状态与路线保留

`floor_run.gd` 在同一次远征中保留已经生成的楼层，下一层使用独立节点数组。重复请求生成当前层不会重置地图、待结算战斗或补给。`floor_snapshot(level)` 返回深拷贝，查看与修改快照不会改变运行状态，未抵达楼层返回空数组。

每次 `setup()` 创建独立 `run_id`；节点 `key` 由远征 ID、层号与局部节点 ID 组合。同种子新远征生成相同地图类型，但身份独立。测试可显式传入远征 ID；正式游玩自动生成。当前身份只在内存中，持久化与恢复后复用该身份属于后续存档工作。

| 字段 | 当前含义 |
| --- | --- |
| `visited` | 已进入节点；进入待结算战斗时即记录 |
| `cleared` | 战斗胜利后清理；营地与补给不设置 |
| `reward_claimed` | 营地恢复或补给已领取；当前战斗无物品奖励，保持 false |
| `done` | 当前下潜规则中的节点完成状态，决定后续可达性；返程通过独立游标判断下一站，不复用该下潜限制 |
| `route` | 按顺序记录已通过节点的完整 key，包含跨层出口与入口，只含所选分支 |
| `pending` | 当前待结算战斗的局部节点 ID，与当前层组合定位；战胜后才加入 `route` |
| `phase` | descending 下潜、returning 返程、returned 已回城、failed 失败；`completed` 仅表示已抵达最深层出口 |
| `deepest_floor` | 本趟最深抵达层数，返程时保持不变 |
| `failed` | 本趟战斗失败后终止，即使回写角色仍有生命也不能继续改道 |

节点状态在失败后保留，重新 `setup()` 才清空旧远征、路线及领取记录。当前没有刷新轮次、远征时间或恢复接口；历史与返程进度仅驻内存，尚不构成正式存档。

## 返程、刷新与地图提示

玩家在一趟远征中从第一层逐层下潜，决定返程时沿本次实际走过的路线向上。普通战斗节点清理后可以重新生成怪物；返程再次进入已刷新节点时，玩家选择交战或避战。避战有损失，并可受角色速度、生命状态和道具影响。完整体验与样例见 [整体玩法设计](../游戏整体/整体玩法设计.md)。

建议使用可复现的远征时间推进刷新：每个普通战斗节点在被清理时决定一个随机刷新阈值，之后移动、战斗和休整增加远征时间。阈值与刷新编队随机化，受楼层生态约束。真实停留在菜单中的时间是否计入待确认。首领、宝箱、眷族任务节点和一次性奖励独立管理，不能因普通怪物刷新重复领取。

地图图标是刷新反馈：刚清理时颜色变浅；随着进度从底向上恢复原色；颜色填满代表已刷新、返程有遭遇。已到访的轮廓始终可辨；悬停显示状态文字或进度，帮助色觉差异玩家判断。刷新时间的随机值一经确定即保存，图标进度与实际判定应一致。

避战前显示可支付的代价和预计后果。建议用节点威胁与角色速度、剩余生命、探路能力、负重及道具计算有限损失；可以研究生命、常见物品或额外时间等方案。没有可支付方案时仍可交战，避免强制死局。具体公式、是否允许返程在已探索分叉改道，以及单趟刷新密度待原型验证。

当前 Demo 已支持原路返程，清理过的战斗节点直接通行。刷新进度与避战待 N3b／N4b 接入；完整风险体验继续用两至三层短流程验证。

## 当前返程骨架与后续规则

N4a 按以下原路与摘要规则实现为可验收原型；完整游戏的改道与收益规则仍可继续迭代。后续风险规则按 [开发计划](../游戏整体/项目管理与开发计划.md) 的 N3b、N4b 推进：

- 地图点击“开始返程”后，只能逐步逆序返回；可以点击高亮的上一节点或右上返程按钮。跨层时从本层入口返回上一层出口，使用原地图。返程后本趟不再下潜，营地与补给不重新领取；当前清理过的战斗节点不再触发遭遇。
- 首层入口点击“回到城市”，生成一次摘要：最深抵达层数、清理战斗次数、剩余生命与两类药水。回城后禁止继续移动或重复结算；此页尚无城市设施或永久收益。材料、金币与保存随 M2 接入。
- 最深层出口允许开始返程，首层入口也可直接回城。战斗待结算、失败或生命耗尽时禁止开始返程。地图的“放弃并回主菜单”直接退出，不生成成功回城摘要。
- `return_target()` 提供下一站快照，`step_return(expected_key)` 校验实际目标再移动；旧按钮重复提交不多走一步。`return_summary()` 提供隔离副本，重新出发清空旧摘要。
- N3b 先采用离散远征行动时间，菜单停留与预览不推进时间；行动刻度、刷新区间与遭遇轮次在实现前细化。
- N4b 先验证一种明确展示的生命避战代价，不允许扣到死亡；无法支付时保留交战。数值与速度关系需原型验证。
- 失败沿用当前 Demo 的本趟终止；正式长期损失与异常恢复在 [角色存档与长期成长](../角色系统/角色存档与长期成长.md) 中收敛。

## 后续节点与怪物之宴

精英、首领、商店、神明事件与安全楼层待实现。几十层按区域划分主题和难度，具体总数、每层节点量、固定与随机内容比例待确认。

## 返程骨架手动验收

使用包含 N4a 的分支，在 Godot 4.7.2 中打开项目并按 F6 运行 `Scenes/UI/main_menu.tscn`，或按 F5 运行主场景；进入“开始旅程”→“逐层探索”。

1. 在第一层入口点击“开始返程”→“回到城市”。应显示“平安归来”，最深层为 1、清理战斗为 0；只有返回主菜单入口，不能再走地图。
2. 重新开始探索，完成首场战斗并走营地，记下生命与药水，再点击“开始返程”。应只高亮实际来路的上一站，前方和未选分支禁用。
3. 点击上一战斗节点，再回入口。应直接通行、没有新战斗，生命与药水保持返程开始时数值，回城摘要清理次数准确。
4. 重新探索到第二层入口，开始返程并点击右上“沿原路返回”。应回第一层出口，原地图与完成标记保留；逐节点回经营地和补给时资源不增加。
5. 回城后返回主菜单并重新探索。应从第一层、新路线状态开始，旧摘要不再显示。将窗口缩到 960×540，返程按钮、下一站及摘要应完整可读。

自动化另覆盖三层最深出口返程、重复回城、旧目标重复回调、失败／战斗中拒绝返程。用户需确认操作清晰度和节奏；刷新、避战、正式城市、保存与长期收益不在本轮验收范围。

# 地下城推进与怪物之宴

状态：下潜地图、历史楼层、自由选择向上路线的返程、按移动步数刷怪、单次回城摘要及地图手动保存／继续已实现。最小城市整备与战利品持有已接入，交战／绕行选择已接入，完整城市待实现。当前规则优先服务完整 Demo，数值随试玩调整。

## 已确定方向与地图结构

每次远征从第一层出发，每层包含入口、三步分支和出口。下潜沿连线向下一步移动；返程沿连线反向向上，可以选择下潜时没有经过的分支。历史路线用于记录经历，不限制返程选路。已到访节点可以重复通行；怪物是否在场和节点是否到访分别显示。可以随时在地图点击“向上返回”与“继续深入”切换方向；实际仍需沿连线逐节点移动。只有点击第一层入口的“回到城市”才结束本趟，向上返回期间可以再次深入。

返程从本层入口回到上一层出口，再自由选择该层的上行分支；第一层入口连接城市。战斗未结算时不能移动、切换返程或回城；失败终止本趟。

## 节点信息可见范围

只显示已到访节点，以及当前方向下一步可直接选择节点的具体情况。其他节点保留位置和连线，统一显示“未到访／未知”，隐藏类型、怪物、奖励、刷新倒计时和进度条，悬停也不透露这些信息。靠近但未实际到访的分支离开后恢复未知；切换深入／返回时按新的可选路线更新显示。已到访节点始终保留详情，怪物刷新不会清除到访记录。重新进入历史楼层沿用该层到访状态；新远征重新计算可见范围。

## 按步数刷新

用户确定：每成功走一步，怪物刷新倒计时减少一个单位。现实时间流逝、停留、查看界面、切换返程、战斗回合、战斗结算与第五层休整站服务均不推进计时。

当前 Demo 的计步边界：一次合法的节点移动、跨层返回或回城各算一步。下潜点击出口并自动抵达下一层入口合为一次移动；生成地图本身不额外计步。非法选择、重复提交、战斗锁定期间的移动请求均不计步。

- 初始战斗节点有怪物；战胜后开始倒计时。Demo 暂用 3–5 步，按种子、楼层、节点和清理次数确定，供试玩调整。
- 每步先更新全部已生成楼层的倒计时，再检查目的地。目标原本剩 1 步时，进入就会刷新并触发战斗，按钮悬停明确提示这一边界。
- 倒计时到 0 后怪物保持在场，不继续扣成负数或重复刷新。再次战胜后开始新一轮倒计时。
- 所有楼层共用移动步数，离开当前层也继续推进历史层倒计时。预览、读取快照不消耗随机数或重新抽取阈值。
- 已到访或下一步可选的节点显示剩余步数、怪物是否在场及刷新进度条。节点始终标明“已到访／未到访”，刷新不会擦除到访记录，已使用的营地／补给标明“已休整／已领取”。当前采用文字与进度条反馈，底部向上恢复角色图标颜色留待美术表现迭代。

返程时，未走过的战斗分支和已经刷新的节点均正常触发战斗，胜利后继续返程；未刷新的清理节点直接通行。第三层第一步上方战斗分支使用守关队长，其余普通／重甲／迅足哥布林按节点内容选择；队长同样遵循移动刷新。敌人变体已接入，敌方多成员编队待开发。


## 当前敌人变体与预告

第一层 1a 普通哥布林、1b 迅足哥布林；第二层 1a 为重甲。其余战斗节点按楼层／位置固定类型，第三层 1a 守关队长保持独立机制。生成类型写入节点 `enemy_kind`，清理、刷新、返程和保存读取都保留；旧记录缺失此字段时沿用普通哥布林，队长位置保留队长，避免读旧档抽成新敌人。

| 类型 | 基础生命／AC／命中／敏捷 | 行为与对策 |
| --- | --- | --- |
| 普通哥布林 | 22／12／+3／+1 | 普通攻击 1d6+1 |
| 重甲哥布林 | 26／15／+2／+0 | 高防御、慢先攻；瞄准提高命中，灼烧药水直接伤害 |
| 迅足哥布林 | 18／11／+4／+5 | 攻击 d20 掷两次取高；被攻击成员自身闪避抵消优势，改为单骰 |
| 守关队长 | 44／13／+4／+1 | 蓄力一回合后 1d10+4 重击 |

普通／变体生命每深一层 +1，增加最多 20；队长保持 44。迅足与闪避相抵时不再掷额外骰，其他敌人打闪避成员仍掷两次取低。双人敌人仍随机选择存活成员，闪避只保护自身。变体复用哥布林图调色占位；正式生态、美术和数值仍待迭代。

合法近处／已到访节点显示类型，悬停和遭遇窗口展示生命、防御、命中、敏捷与机制。未知节点不显示名称、统计或机制，远处无法打开预览。确认交战使用预览同一类型，取消不计步，绕行成本仍为一瓶灼烧药水。战斗显示重甲／迅足预告；战利品、普通讨伐计数、共享成长与 GM 结算沿原规则。

验收：F5 → 新旅程出发 → 对比第一层两条可选路线；迅足节点悬停／点击显示两骰优势与闪避提示，取消后步数不变。确认迅足交战，在自身回合选闪避后结束，日志应见迅足打闪避成员 `roll_mode=normal` 且只有一个 d20；不闪避时为 advantage、两个骰取高。第二层上方第一步查看重甲 AC 15，灼烧药水仍直接扣 8 生命。清理保存、退出再读类型保持，刷新后仍同类；远处节点仍未知。

`test_enemy_variety.gd` 验证类型、未知边界、预览不变状态、旧档补普通、未知内容拒绝、磁盘恢复、实际 UI 预览／交战一致、GM、刷新及多种种子下闪避取消优势。日志包含攻击原始骰、选定骰、模式、敌人内容 ID 与命中结果，检查工具核对取高／取低／抵消、骰子数量、类型与命中；十九组 Godot、六次独立进程恢复和十一项 Python 检查通过，960×540 遭遇窗口已检查。用户数值与体验待验收。

## 当前交战与绕行 Demo

点击下一步怪物节点先显示遭遇选择，预览本身不移动。包括怪物已在场和清理节点剩 1 步、移动时即刷新的情况。深入和返回共用规则，远处未知节点不能打开预览。

- 交战：确认才移动 1 步并进入战斗，胜利沿用正常清理与战利品。
- 掩护绕行：消耗 1 瓶灼烧药水，移动 1 步抵达该节点；到访和路线正常记录，怪物保留且不发奖励，不增加讨伐次数或完成队长目标。队长也可绕行，再经过时仍需处理遭遇。
- 无药时禁用绕行，保留交战和取消；取消不计步、不扣资源。非法目标、库存不足、重复提交先拒绝，避免部分消耗。
- 灼烧药水也能用于战斗，城市售价暂定 4 金币／瓶。绕行是现有道具的第二种用途，数值为可调整 Demo 参数；不计额外战斗时间或刷新步数。

绕行后的地图安全点可手动保存；读取恢复库存、路线、到访及在场怪物。已清理又刷新的怪物绕行后保留其清理历史，无新清理次数。`enter(id, avoid)` 与 `step_return(key, avoid)` 在移动前重新校验，默认仍为交战。

## 节点与奖励

`floor_run.gd` 默认 30 层，可配置；每层 8 节点，同一拓扑模板按种子变化部分类型。30 为演示参数，尚无 30 套独立主题。第一步必为战斗，第二步至少一条营地路线。第三层 1a 为阶段队长，不改节点拓扑和到访状态；靠近／已到访时才显示名称，其他分支仍可自由选择。队长机制见 [回合制战斗](../战斗系统/回合制战斗.md)。

| 节点 | 行为 |
| --- | --- |
| 战斗 | 有怪物时进入战斗；清理后等待移动步数刷新 |
| 营地 | 首次进入恢复 10 HP，受上限限制；返程首次进入也可领取，重复经过不再恢复 |
| 补给 | 首次进入获得 1 瓶治疗药水，重复经过不再发放 |
| 出口 | 下潜进入下一层，最深层停止下潜并可返程；返程时可选择连入出口的任一上行分支 |

刷新只改变战斗遭遇，不重置营地、补给、唯一奖励或任务领取。当前战斗每次胜利结算获得 3 金币和 1 铁片，刷新后再次胜利可再获得，重复提交结算不重复发放；回城摘要不另发奖励。首领、宝箱与任务需各自维护领取边界。

## 运行时状态与结算

| 状态 | 当前职责 |
| --- | --- |
| `run_id`、节点 `key` | 每次出发独立身份；key 由远征 ID、楼层与局部节点 ID 组成 |
| `route`、`return_route` | 分别保留下潜和返程经过的完整节点 key，交战胜利或成功绕行后加入 |
| `visited`、`cleared`、`done` | 到访、曾清理、下潜节点完成分别记录，刷新不擦除历史 |
| `enemy_active` | 当前怪物是否在场，与历史清理状态独立 |
| `respawn_in`、`respawn_total`、`clear_count` | 剩余刷新步数、本轮总步数、清理次数 |
| `steps_taken`、`battles_won` | 本趟合法移动次数、累计战斗胜利次数（包含刷新后战斗） |
| `phase`、`pending` | 下潜／返程／回城／失败阶段，以及当前待结算战斗 |

`begin_return()` 与 `begin_descent()` 只切换方向，不推进计时。旧层出口可通过 `descend_floor(expected_floor)` 重新进入下层入口，历史层直接激活原节点数组。

`return_targets()` 列出全部合法返程目的地；仅剩一个目标时 `return_target()` 为快捷按钮提供目标。`step_return(expected_key)` 校验目标后计步、移动或进入遭遇。战斗胜利后回写位置，保留返程阶段。

`floor_snapshot()` 和 `return_summary()` 返回深拷贝。第一层入口回城只生成一次“平安归来”摘要，展示最深层数、累计胜利次数、生命与两类药水。回城后不能继续移动；地图的“放弃并回主菜单”不生成成功摘要。地图“保存并退出”可在当前角色下新增或覆盖记录，主菜单分级读取或继续最近记录恢复原远征；未保存的变化不写磁盘。回城后可进入城市整备，城市与地图手动保存；失败暂不覆盖记录，具体边界与异常恢复见 [角色存档与长期成长](../角色系统/角色存档与长期成长.md)。

## 手动验收

使用当前分支，Godot 4.7.2 按 F5 → 开始旅程 → 进入城市 → 从第一层出发。

1. 完成首场战斗，记录该节点的“刷新还需 X 步”。停留或查看地图后数字不变；走到第二步营地后应恰好减少 1。
2. 在营地点“向上返回”。第一步两条战斗分支都应高亮；可选择下潜没有走过的那条，并正常触发战斗。胜利后仍处于返程，可继续到入口。
3. 另一趟多走几步再返程：倒计时每次移动减少 1，到 0 显示“怪物在场”。进入已刷新节点重新战斗；胜利后重新显示 3–5 步。
4. 当目标剩 1 步时悬停查看提示，进入应遇敌；已领取的营地与补给再次经过不发放，未领取的分支可首次领取。
5. 抵达第二层后向上返回到第一层出口，点“继续深入”→“进入第 2 层”。应回到第二层原地图，到访、营地领取和刷怪状态保留。
6. 退回营地后点“继续深入”，已走过的向下节点应可再次选择。反复切方向，移动总步数和倒计时不变。未使用营地可恢复 10 HP；已标“已休整”的营地不会重复恢复。
7. 新开探索时只应看见第一步分支详情，后续节点显示“未知”；前进一步揭示下一步，未选择的同排分支恢复未知。切换返回方向应揭示可选的上行分支，悬停未知节点不泄露类型。
8. 到访过的怪物刷新后仍显示“已到访”；最后在第一层入口点击“回到城市”才生成摘要。缩小到 960×540 后按钮与状态应完整可读。

自动化覆盖非法移动不计步、跨层同步倒计时、归零边界、重复结算、返程遭遇、摘要隔离与重开。自动化同时覆盖第十层退回第九层营地再深入、旧层重新激活和最深出口往返。存档专项覆盖恢复与错误处理，验收见存档文档。用户确认选路清晰度、刷新压力和绕行成本；完整城市、职业与队伍成长待实现。

绕行验收：新角色出发 → 点击第一步怪物 → 取消，步数和药水应保持；再点并选绕行，灼烧减 1、步数 +1、怪物仍在场、无金币铁片。营地切返回 → 选未走分支绕行；无药时绕行禁用、可交战。回城买灼烧药水，扣 4 金币得 1 瓶。绕过三层队长不会完成目标。保存并继续保留结果。`test_encounter_choice.gd` 覆盖这些操作及剩 1 步刷新、重复提交和磁盘恢复；960×540 弹窗已检查，体验待用户验收。

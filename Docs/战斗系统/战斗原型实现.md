# 战斗原型实现

状态：设计已确定，待实现。本文是第一阶段横版卡牌战斗原型的实现规格，规定模块划分、数据结构、结算顺序、初始数值与验收标准。战斗设计规则见 [卡牌战斗](卡牌战斗.md)，资源规则见 [资源与体力](资源与体力.md)，界面要求见 [战斗操作与界面](../战斗与操作/战斗操作与界面.md)。

原型目标是验证没有抽牌随机性的卡牌战斗是否成立，范围为洛恩单人对两名敌人。美术素材尚未制作，界面采用色块、边框与文字的占位表现。战斗逻辑与界面分离，素材到位后只替换表现层。

## 模块划分

战斗逻辑层不依赖任何节点与界面，可在无头环境下直接测试。界面层只读取逻辑层状态并转发玩家输入，不持有战斗规则。

| 文件 | 职责 |
| --- | --- |
| `Scripts/Battle/card_library.gd` | 卡牌目录，按 `card_id` 提供卡牌数据 |
| `Scripts/Battle/enemy_library.gd` | 敌人目录，按 `enemy_id` 提供敌人数据 |
| `Scripts/Character/character_library.gd` | 角色目录，提供洛恩的战斗属性与持有卡 |
| `Scripts/Battle/combatant.gd` | 战斗单位的属性、资源扣减与伤害结算 |
| `Scripts/Battle/timeline.gd` | 行动顺序推进与未来行动预览 |
| `Scripts/Battle/battle_state.gd` | 战斗流程、出卡结算、敌人行动与胜负判定 |
| `Scripts/Core/game_flow.gd` | 自动加载单例，负责场景切换与角色数据传递 |
| `Scripts/Battle/battle_screen.gd` | 战斗界面，展示时间轴、战场、卡牌区、资源区与日志 |
| `Scenes/Battle/battle.tscn` | 战斗场景，根节点为 `Control`，界面在脚本中构建 |

三个目录脚本均采用字典常量加静态 `resolve` 方法的形式，与既有脚本保持一致。`resolve` 返回深拷贝并写入自身标识，调用方可以安全修改返回值。角色目录的 `resolve` 在标识不存在时回退到默认角色。

代码风格沿用项目现状：制表符缩进，中文注释且只在必要处书写，不使用 `class_name`，脚本之间通过 `preload` 引用。界面全部在脚本中构建，`.tscn` 只保留根节点与脚本挂载，做法参考 `Scripts/UI/main_menu.gd`，并沿用其配色常量。

## 数据结构

### 卡牌

字段：`display_name`、`source`、`sp_cost`、`mp_cost`、`time_cost`、`target`、`effects`、`keywords`、`uses`。`uses` 仅补给卡具备，表示携带数量；其余卡不限次数。

`target` 取值与含义：

| 取值 | 含义 |
| --- | --- |
| `self` | 作用于施放者自身 |
| `enemy_single` | 作用于施放者敌对阵营的单个单位，需要指定目标 |
| `enemy_all` | 作用于施放者敌对阵营的全部存活单位 |

敌对阵营按施放者的 `team` 解析。我方打出 `enemy_all` 命中全部敌人，敌人打出 `enemy_all` 命中我方全体。

`effects` 为数组，每项是一个字典，`type` 决定其余字段：

| type | 字段 | 含义 |
| --- | --- | --- |
| `damage` | `amount` | 对目标造成伤害，按目标的防御系数结算 |
| `heal` | `amount` | 恢复生命 |
| `restore_sp` | `amount` | 恢复体力 |
| `restore_mp` | `amount` | 恢复魔力 |
| `guard` | `ratio` | 目标进入防御，受到的伤害乘以该系数，直到其下一次行动开始 |
| `delay` | `amount` | 推后目标的下一次行动时点，并中断其蓄力 |

`heal`、`restore_sp`、`restore_mp`、`guard` 在当前卡表中只出现在 `self` 卡上，实现时仍按目标解析，便于后续扩展到队友。`delay` 直接加在目标的行动时点上，不经过速度换算。

### 战斗单位

字段：`id`、`display_name`、`team`、`max_hp`、`hp`、`max_sp`、`sp`、`max_mp`、`mp`、`speed`、`row`、`card_ids`、`card_uses`、`charge_card_id`、`guard_ratio`、`next_act`、`pending_card`、`join_order`。

`team` 取值 `ally` 与 `enemy`。`row` 取值 `front` 与 `back`，本阶段只用于界面呈现，不影响结算。`card_uses` 记录补给卡剩余次数，在创建单位时按卡牌的 `uses` 初始化。`guard_ratio` 默认 1.0。`pending_card` 保存已宣告尚未释放的蓄力卡。`join_order` 用于行动顺序的最终排序。

需要提供的方法：`is_alive()`、`is_fatigued()`、`fatigue_multiplier()`、`can_pay(card)`、`pay(card)`、`take_damage(amount)`、`heal(amount)`、`restore_sp(amount)`、`restore_mp(amount)`、`default_attack_card_id()`、`recovery_time_cost()`。

保底行动在 `can_pay` 与 `pay` 中特殊处理：普通攻击与防御在任何资源状态下都返回可用，且不扣减资源。

## 时间轴规则

`next_act` 表示该单位下一次行动的时点，数值小者先行动。相同时点按速度高者优先，速度仍相同按 `join_order` 升序。

行动后推进：`next_act += time_cost * 100.0 / speed * fatigue_multiplier`。速度 100 为基准值。

疲劳：体力低于上限的 20% 时 `fatigue_multiplier` 取 1.25，其余取 1.0。该系数在推进时实时计算，因此扣除体力后当场进入疲劳会立即影响本次行动的推进量，体力恢复后立即失效。

预览：`preview(count)` 在单位状态的副本上模拟后续若干次行动，**不得修改任何真实状态**。返回的每项包含单位、行动时点与该次行动是否处于蓄力。模拟各单位下一次行动的耗时按以下规则估算：

- 已宣告蓄力的单位，下一次行动是释放，按其收招耗时估算。
- 具备蓄力卡且未宣告的敌人，下一次行动是宣告蓄力，按蓄力卡耗时估算。
- 其余敌人按其普通攻击卡耗时估算。
- 我方单位尚未决定出哪张卡，统一按普通攻击耗时估算。

预览是玩家判断抢先与打断的唯一依据，估算规则需要与界面提示一致。

## 结算顺序

`play_card(actor, card_id, target)` 必须按以下顺序执行，顺序错误会产生玩家可感知的错误行为：

1. 检查战斗仍在进行，且 `actor` 确实是当前应当行动的单位。
2. 检查卡牌可用（资源充足、次数未耗尽）。
3. **检查目标合法**：`enemy_single` 要求目标非空、存活且属于敌对阵营。
4. 清除 `actor` 的防御状态，将 `guard_ratio` 重置为 1.0。
5. 扣减体力、魔力与补给次数。
6. 结算卡牌效果。
7. 按卡牌耗时推进时间轴。
8. 移除失去战斗力的单位，更新胜负状态，发出状态变化信号。

第三步必须早于第四步。目标非法时直接返回失败且不产生任何副作用，避免玩家误点空目标后丢失防御状态。

## 敌人行动

敌人由简单规则驱动，不做搜索与评分。每次敌人行动同样先清除其防御状态。

具备蓄力卡的敌人按两步执行：

1. **宣告**：将蓄力卡写入 `pending_card`，按蓄力卡的耗时推进时间轴，并在日志与时间轴预览中标出。该次行动不产生伤害。
2. **释放**：下一次轮到它时结算蓄力卡效果，清空 `pending_card`，按该敌人**普通攻击的耗时**推进时间轴作为收招。

等待时间已经体现在宣告步的推进中，释放步按普通攻击耗时收招，避免蓄力总代价翻倍导致敌人失去威胁。

受到 `delay` 效果时清空 `pending_card`，该次强力攻击作废，并在日志中说明蓄力被打断。

不具备蓄力卡的敌人打出其普通攻击卡，目标为随机存活的我方单位。

## 战斗流程接口

`battle_state.gd` 对外提供：

- `setup(allies: Array, enemies: Array) -> void`：初始化战斗单位与时间轴。
- `current_actor() -> RefCounted`：返回当前应当行动的单位，战斗结束时返回空。
- `available_cards(actor) -> Array`：返回该单位的全部卡，每项附带 `can_play` 与 `reason`。资源不足与次数耗尽的卡**保持在返回结果中**，由界面置灰呈现。
- `play_card(actor, card_id, target) -> bool`：按上节的结算顺序执行，返回是否成功。
- `advance_until_player_turn() -> void`：连续执行敌人行动，直到轮到我方单位或战斗结束。
- `preview(count: int) -> Array`：转发时间轴预览，供界面使用。
- `outcome` 属性：取值 `ongoing`、`victory`、`defeat`。

信号：`state_changed`、`log_appended(text: String)`、`battle_finished(outcome: String)`。界面只通过信号刷新显示，不主动轮询。

生命降到 0 及以下的单位失去战斗力并退出时间轴。敌方全部失去战斗力判定为 `victory`，我方全部失去战斗力判定为 `defeat`。

战斗结束后资源保留在角色数据上，不做补满。界面在收到 `battle_finished` 时将角色的生命、体力、魔力与补给剩余次数写回 `GameFlow.active_character`，为后续的楼层连续推进预留结转接口。

## 场景流程

`Scripts/Core/game_flow.gd` 作为自动加载单例 `GameFlow`，在 `project.godot` 的 `[autoload]` 段注册，持有 `active_character` 字典，提供 `start_battle(character_id)` 与 `return_to_menu()`，切换场景失败时 `push_error`。

主菜单的角色弹层增加进入战斗的入口，调用 `GameFlow.start_battle("lorn")`。现有的 `new_game_requested` 信号与焦点行为保持不变，`Tests/test_main_menu.gd` 的既有断言必须继续通过。

战斗场景初始化时从 `GameFlow.active_character` 取角色数据，为空时回退到 `character_library` 的默认角色，保证直接运行战斗场景也能工作。敌人固定为洞穴狼与石拳巨像。

## 初始数值

这些数值用于跑通流程与手感验证，调整不需要改动结构。

角色洛恩：生命 120，体力 100，魔力 40，速度 100，前排。

| 卡牌 | `card_id` | 体力 | 魔力 | 耗时 | 目标 | 效果 |
| --- | --- | --- | --- | --- | --- | --- |
| 普通攻击 | `basic_strike` | 0 | 0 | 60 | `enemy_single` | 伤害 10 |
| 防御 | `guard` | 0 | 0 | 40 | `self` | 防御系数 0.5 |
| 迅击 | `swift_cut` | 8 | 0 | 45 | `enemy_single` | 伤害 12 |
| 重斩 | `heavy_slash` | 18 | 0 | 100 | `enemy_single` | 伤害 26 |
| 火焰箭 | `flame_arrow` | 4 | 12 | 70 | `enemy_single` | 伤害 22 |
| 打断突刺 | `interrupt_thrust` | 12 | 0 | 55 | `enemy_single` | 伤害 8，推后目标 60 |
| 干粮 | `ration` | 0 | 0 | 50 | `self` | 恢复体力 30，携带 2 份 |
| 药水 | `potion` | 0 | 0 | 50 | `self` | 恢复生命 40，携带 1 份 |

普通攻击与防御为保底行动，任何资源状态下都可使用。

敌人洞穴狼 `cave_wolf`：生命 60，速度 120，普通攻击伤害 8，耗时 50。

敌人石拳巨像 `stone_colossus`：生命 110，速度 70，普通攻击伤害 12，耗时 70；蓄力卡「碎地重击」耗时 120，目标 `enemy_all`，伤害 30。

敌人的攻击卡与蓄力卡同样定义在卡牌目录中。

## 界面要求

分区按 [战斗操作与界面](../战斗与操作/战斗操作与界面.md) 布置，使用容器节点完成布局，避免写死坐标：

- **顶部行动时间轴**：展示未来六次行动的单位名称，我方与敌方用颜色区分，蓄力项加明显标记，当前行动者高亮。
- **中部战场**：我方在左、敌方在右。每个单位一个面板，显示名称、生命条、当前与最大生命、防御与蓄力状态。敌方面板可点击用于选择目标，失去战斗力的单位置灰。
- **底部卡牌区**：展示当前行动单位的全部卡，每张显示名称、体力与魔力消耗、耗时，补给卡额外显示剩余次数。不可用的卡保持可见并置灰，不可用原因通过文字或提示呈现。
- **左下资源区**：生命、体力、魔力的数值与条；体力低于上限 20% 时显示明确的疲劳提示。
- **右下战斗日志**：监听 `log_appended` 逐条追加，保留最近十余条，新条目在下方。

必须满足的可读性条件，这些在原型试做中出现过问题：

- 1280×720 下**八张卡全部完整可见**，不依赖横向滚动。卡片可以缩小或分两行排列。
- 生命条与资源条使用可区分的填充颜色，我方与敌方区分开，空条与满条一眼可辨。
- 单位面板的内容在面板内垂直居中，避免面板高度撑满而内容挤在顶部。
- 各分区之间留出边距，任何文字不被裁切或重叠。

操作流程：点击卡牌选中并给出明显的选中态；`self` 与 `enemy_all` 的卡直接生效；`enemy_single` 的卡需要再点击一个敌方面板确认。出卡后调用 `advance_until_player_turn` 推进敌人行动并刷新界面。鼠标右键或 Esc 取消当前选中；没有选中卡时按 Esc 返回主菜单。战斗结束时显示结果面板与返回主菜单的入口，并禁用卡牌区。

关键控件与出卡逻辑需要作为脚本成员变量与方法暴露，便于无头测试从外部驱动。

## 验证方式

`Tests/test_battle_logic.gd`，无头运行，覆盖：

- 时间轴顺序正确，速度高的单位先行动，`preview` 不改变真实状态。
- 出卡正确扣减体力与魔力，伤害结算正确。
- 体力低于上限 20% 时疲劳系数为 1.25，并影响行动推进量。
- 防御使下一次受到的伤害减半，该单位自己行动后防御失效。
- 目标非法时出卡失败且不清除防御、不扣减资源。
- 石拳巨像的蓄力两步执行；对其使用打断突刺后蓄力作废。
- 补给卡次数耗尽后 `can_play` 为 false，且该卡仍出现在 `available_cards` 结果中。
- 体力为 0 时普通攻击与防御仍然可用。
- 敌人全灭判定 `victory`，我方全灭判定 `defeat`。

`Tests/test_battle_screen.gd`，无头运行，覆盖界面各区完成构建、卡牌区按钮数量等于持有卡数、不可用的卡仍存在于界面中、循环出卡直到战斗结束且结果面板出现、日志与资源显示随出卡变化。循环需要设置次数上限防止死循环。

`Tests/capture_battle.gd`，截取战斗画面用于人工检查布局与可读性，写法参考 `Tests/capture_main_menu.gd`。截图失败时必须以非零退出码结束，**不得写入占位图像充当结果**。

测试脚本在断言失败时必须以非零退出码结束，确认 Godot 4.7 下的实际行为后再选择断言方式，避免失败仍然输出通过。

运行方式：

```
godot --headless --path . --script Tests/test_battle_logic.gd
godot --headless --path . --script Tests/test_battle_screen.gd
godot --headless --path . --script Tests/test_main_menu.gd
```

截图脚本需要真实渲染，在带窗口的模式下运行。

## 实现顺序建议

1. 三个目录脚本与战斗单位，先让数据可以取出。
2. 时间轴与战斗流程，配合 `Tests/test_battle_logic.gd` 边写边验证。
3. 场景流程单例与主菜单入口。
4. 战斗界面与 `Tests/test_battle_screen.gd`。
5. 截图检查布局可读性，按界面要求一节的条件逐项核对。

逻辑层完成并通过测试之前不要开始界面层。

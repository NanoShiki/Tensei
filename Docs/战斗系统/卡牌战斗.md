# 卡牌战斗

状态：策划初稿，待实现。战斗形式、卡牌定位、时间轴与站位方向已确定；具体数值、关键词表与敌人机制清单属于提案，需要通过原型验证。

## 战斗形式

局内战斗采用横版画面，我方队伍在左、敌方在右，双方以立绘或战斗姿态呈现。队伍规模暂定 3 人，具体上限随原型确定。玩家手动指挥全部队员；联机时各玩家操作各自的角色，规则不变，见 [玩家主机联机](../联机/玩家主机联机.md)。

战斗不使用自由移动与实时操作。角色的位置由站位表达，行动由卡牌表达，节奏由时间轴表达。

## 卡牌的定位

卡牌是能力的统一表示。武器、装备、职业技能、补给品和神明赐福都以卡牌呈现，玩家在城市里配装就等于组牌。

**不采用抽牌、过牌与弃牌堆。** 战斗中角色的全部卡常驻可见，能否使用取决于资源是否足够、携带次数是否用尽、以及当前时机是否合适。这样长期培养的结果始终可预期，与一档一角色的成长设计一致。

由此带来的要求：战斗的变化必须由其他部分提供，否则会退化成固定连招。变化来源见 [整体玩法设计](../游戏整体/整体玩法设计.md) 的深度来源一节，本文负责其中的行动时机与站位部分。

### 卡牌分类

| 类别 | 来源 | 使用方式 |
| --- | --- | --- |
| 武器卡 | 装备的武器 | 提供基础攻击与武器专属动作，更换武器即更换这组卡 |
| 技能卡 | 职业与转职 | 主动打出，通常消耗 MP |
| 装备卡 | 护甲、饰品 | 常驻生效，不主动打出，在战斗界面单独展示 |
| 补给卡 | 局外采购并携带 | 一次性消耗，数量等于携带数量 |
| 赐福 | 局内神明赐福 | 改写已有卡的效果、消耗、耗时或目标范围 |

每张主动卡记录：名称、来源、体力消耗、MP 消耗、行动耗时、目标范围、效果与关键词。关键词用于建立卡与卡之间的联动，例如破甲、流血、蓄力、守护、穿透；完整关键词表在原型阶段确定。

**保底行动**：每个角色始终具备不消耗体力与 MP 的基础行动，至少包含普通攻击与防御。资源耗尽时玩家仍可行动，只是失去强力手段，原因见 [资源与体力](资源与体力.md)。

## 时间轴

出手顺序由时间轴决定，不采用“我方全部行动后再轮到敌方”的回合结构。

建议采用可预览的行动队列：每个单位持有下一次行动的时间值，打出卡后按该卡的行动耗时与单位速度推后。界面展示未来若干次行动的顺序，玩家据此判断抢先、打断与蓄力的取舍。

- **行动耗时**：轻动作短、重动作长。同样的资源下，玩家需要在“抢两次轻击”和“赌一次重击”之间选择。
- **速度**：角色与敌人的速度影响耗时换算，装备与赐福可以改变速度。
- **打断与延迟**：部分卡可以推后敌人的下一次行动，或中断其蓄力。
- **敌人蓄力**：敌人的强力攻击在时间轴上提前可见，玩家可以选择抢输出、打断、防御或换位躲避。这是战斗内的主要博弈点。

具体时间单位、耗时档位与速度换算公式在原型中确定。

## 站位

横版采用前后两排。近战卡默认只能作用于对方前排，远程与法术可以指定后排，部分卡具备穿透或范围形状。位移类卡可以推拉单位或交换排位。

站位承担三件事：承伤分配、射程限制、范围效果的命中数量。排数是否扩展到三排，随原型结果确定。

## 胜负与结算

敌方全部失去战斗力即战斗胜利，进行掉落结算并继续推进楼层。我方全员失去战斗力即战斗失败，失败惩罚与救援规则待设计，涉及损失范围时遵循 [角色存档与长期成长](../角色系统/角色存档与长期成长.md)。

战斗结束后资源不会自动补满，恢复方式见 [资源与体力](资源与体力.md)。

## 第一阶段实现范围

第一阶段只验证核心战斗体验，不实现队伍编成与楼层推进：

- 我方 1 名角色（洛恩）对 2 名敌人，其中一名具备可预览的蓄力攻击。
- 实现时间轴、出卡、体力与 MP 与生命的消耗、保底行动、胜负判定。
- 卡牌数量控制在可验证范围，覆盖轻击、重击、技能、防御与补给各一类。

该范围的程序原型已实现，见 [战斗原型实现](战斗原型实现.md)。验证目标是回答一个问题：没有抽牌随机性的卡牌战斗是否成立。玩法结论出来之前不扩展系统。

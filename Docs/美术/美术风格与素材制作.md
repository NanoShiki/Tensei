# 美术风格与素材制作

状态：设计草案，待实现。纯二维、非像素手绘方向已确定；素材、绑定和动画生产流程尚待动态样例验证。

## 已确定方向

整体美术参考日式西幻，以《地错》与《刀剑神域》为重点、《无职转生》为补充。《刀剑神域》的具体视觉参考范围待风格样张阶段细化。角色、怪物、装备、建筑、界面和特效应形成一致的冒险世界。项目美术素材主要由 AI 代理调用生图模型获得。

局内采用参考《Jotun》《33 Immortals》的非像素二维手绘表现，结合日式西幻角色造型。采用类似《以撒》的俯视角平面移动，角色可上下左右及斜向移动；具体镜头俯角与角色比例待样张确定。整个资产流程采用纯二维制作，排除三维建模和三维预渲染角色流程。立绘、头像和剧情插画可采用更精细的二次元绘制，需保持与局内角色的身份特征一致。

Hades 继续提供即时操作和神明赐福表达的参考。局内美术以本节的二维手绘方向为准。

《33 Immortals》是后续操作模式和二维资产形态的重点参考；《Jotun》补充手绘风格与多方向动画制作参考。具体线条、比例和动态效果通过本项目样张确定。

## 制作依据与可行性边界

- 《Jotun》的开发者复盘确认使用 Toon Boom 制作二维动画并复用绘画内容；主角八向实际绘制五向，再镜像得到其余方向。镜像导致持斧手换边，是原团队接受的取舍。本项目的方向数量及非对称装备镜像规则仍待验证。
- 《33 Immortals》的官方资料展示手绘美术与动画。当前资料尚不足以确认其具体绑定软件或骨骼与逐帧动画的混合方式。
- 生图适合承担场景、部件、武器、立绘以及方向和姿势参考的主要绘画工作。图片仍需要统一比例、透视、光照、透明边缘及连接位置；独立生成的各帧需要检查外形漂移和循环衔接。
- 建议采用“生成素材 → 分层与补全 → 二维绑定 → 共享动作与关键姿势补帧 → 引擎验证”的流程。完整动画集的质量与批量生产效率，需通过可操作样例确认。
- 初期阴影建议采用脚下柔和投影，配合素材明暗和场景光效。复杂动态投影、法线贴图与局部照明按后续需求验证。

## 视觉建议

- 角色通过轮廓、服装、持械方式和施法表现传达职业身份，换装与派生需要保留可辨识的角色特征。
- 城市呈现生活、工坊、商贸和冒险准备氛围；地下城通过地貌、怪物和照明表达深度与危险；安全楼层使用清晰的补给设施与聚集区标识。
- 武器与怪物素材保留可追溯的外形、纹理或颜色关联，让玩家能够理解打造来源。
- 攻击预警、敌我识别、交互目标和掉落物在战斗画面中优先保持可读性。稀有度通过图形、文字与颜色共同表达。

## 生图制作流程

1. 阅读素材所属模块的文档，整理用途、主体、风格、视角、构图、尺寸、背景透明需求及交付形式。
2. 首批生成风格样张和角色或场景参考图，选定视觉基准后持续复用参考，保持系列一致性。
3. 按任务调用生图模型，检查轮廓、装备结构、比例、光照、边缘及批次一致性，必要时继续编辑生成结果。
4. 对采用的素材整理用途、提示词、参考图、规格与项目内路径，记录在对应模块文档或素材目录的说明中。
5. 导入 Godot 后检查实际显示效果；有动画、方向帧或切片需求时，逐项验证衔接和可用性。

角色素材应按身体模板、部件、朝向和必要姿势组织，补全关节及被遮挡的区域。发型、衣物等可选项需要提供能装配的素材组。具体装配与动画规则统一维护在 [角色创建与外观动画](../角色系统/角色创建与外观动画.md)。

## 首轮验证建议

制作一个身体模板、两种头发、两种耳朵、两把普通同类武器及一个特殊武器动作覆盖，验证四向待机、行走和一次攻击。检查实际屏幕尺寸下的轮廓、方向切换、脚底滑动、部件接缝、握持位置、遮挡、阴影、动作切换及兼容回退。四向用于验证起点，正式四向或八向规格待结果确定。

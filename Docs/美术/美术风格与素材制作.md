# 美术风格与素材制作

状态：设计草案，待实现。纯二维、非像素手绘方向已确定；洛恩与哥布林单帧战斗姿态已接入 Demo，完整动画待制作。

## 已确定方向

整体美术参考日式西幻，以《地错》与《刀剑神域》为重点、《无职转生》为补充。角色、怪物、装备、技能、建筑、界面和特效应形成一致的冒险世界。项目美术素材主要由 AI 代理调用生图模型获得。

局内采用横版回合制战斗表现，我方在左、敌方在右，角色以战斗姿态呈现，参考横版队伍构图与博德之门式底部图标分区，《杀戮尖塔》仅用于地图节点表达。整个资产流程采用纯二维制作，排除三维建模和三维预渲染流程。立绘、头像和剧情插画可采用更精细的二次元绘制，需保持与局内角色的身份特征一致。

《Jotun》与《33 Immortals》继续作为非像素二维手绘的表现参考。项目不再采用俯视角平面移动与即时动作操作，这两部作品的操作模式不在参考范围内。

Hades 继续提供神明赐福的表达参考。

## 制作依据与可行性边界

- 生图适合承担角色姿态、敌人、技能图标、立绘与场景的主要绘画工作。图片仍需要统一比例、透视、光照、透明边缘及连接位置；独立生成的各帧需要检查外形漂移与循环衔接。
- 《Jotun》的开发者复盘确认使用 Toon Boom 制作二维动画并复用绘画内容。横版单一朝向的动作量远低于多方向动作，这是本次方向调整带来的制作量收益。
- 建议流程：生成素材 → 分层与补全 → 二维绑定 → 共享动作与关键姿势补帧 → 引擎验证。完整动画集的质量与批量生产效率，需通过可操作样例确认。
- 初期阴影建议采用脚下柔和投影，配合素材明暗与场景光效。

## 视觉建议

预设角色的初始与成长阶段插画采用精细二次元表现，保持同一角色的身份特征。初始平民或学徒穿着与转职后的成长形象形成清楚的阶段变化，具体展示、解锁与生产验证见 [角色插画与成长解锁](../角色系统/角色插画与成长解锁.md)。

- 角色通过轮廓、服装、持械方式和施法表现传达职业身份，换装与派生需要保留可辨识的角色特征。
- 技能图标需要在小尺寸下保持可读：主体清晰、信息层级明确，同类图标在版式上保持一致。
- 敌人的行动、机制与状态必须具备可读的视觉表达，玩家的应对决策依赖这些信息，要求见 [战斗操作与界面](../战斗与操作/战斗操作与界面.md)。
- 城市呈现生活、工坊、商贸和冒险准备氛围；地下城通过地貌、怪物和照明表达深度与危险；安全楼层使用清晰的补给设施与聚集区标识。
- 武器与怪物素材保留可追溯的外形、纹理或颜色关联，让玩家能够理解打造来源。

## 生图制作流程

1. 阅读素材所属模块的文档，整理用途、主体、风格、视角、构图、尺寸、背景透明需求及交付形式。
2. 首批生成风格样张和角色或场景参考图，选定视觉基准后持续复用参考，保持系列一致性。
3. 按任务调用生图模型，检查轮廓、装备结构、比例、光照、边缘及批次一致性，必要时继续编辑生成结果。
4. 对采用的素材整理用途、提示词、参考图、规格与项目内路径，记录在对应模块文档或素材目录的说明中。
5. 导入 Godot 后检查实际显示效果；有动画或切片需求时，逐项验证衔接和可用性。

生图工具的输出可能是套用了 `.png` 扩展名的 JPEG 数据，Godot 会直接拒绝导入。采用前检查文件头，必要时重新编码为真正的 PNG。

## 首轮验证建议

制作洛恩的横版待机、一次攻击与一次受击，加上一名哥布林与一组技能图标，验证横版战斗画面的整体观感：角色与技能的尺寸关系、战场与界面的层次、当前行动者与状态的可读性。四向与八向动作不再需要，相关素材已移除。

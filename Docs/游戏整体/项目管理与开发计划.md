## 项目目标与当前结论

已确定方向：日式西幻、非像素二维手绘、横版回合制地下城冒险。每人每回合默认行动一次；玩家长期培养角色、装备和眷族队友，每趟从第一层下潜，通过返程带回收获，再进行锻造、升级与转职。单人与联机沿用角色，Steam Listen Server 联机与创意工坊是产品目标。独立终局肉鸽在常规冒险及养成稳定后制作。

**当前处于战斗与逐层地图原型阶段。** 可运行主菜单、洛恩对哥布林的单人战斗、默认 30 层的下潜地图。城市往返与长期养成尚未形成可玩的完整循环。N3a 历史楼层与已走路线基础已实现并通过自动化检查；下一步收敛返程切片规则，再接入 2–3 层返程交互。M0 的用户试玩与素材认可持续进行。

30 层使用同一拓扑模板，仅部分节点类型随种子变化；这个参数不代表 30 层正式内容完成。探索、角色生命和药水仅在内存中延续；菜单的音量与全屏配置已经持久化，角色存档尚未实现。

## 依赖关系与实施边界

以下按可单独验证的小步推进。M0 的技术回归是每次交付的门槛；用户手感、美术认可单列跟踪，可与不依赖视觉定稿的状态模型工作并行。

```text
现有原型 → M0 技术回归（每批变更持续执行）
  → M1a 历史楼层与路线基础（N3a，已实现）
  → M1b 返程与回城骨架（N2 的路线／结算切片规则 → N4a）
  → M1c 刷新、交战／避战与第二类怪物（N2 的时间／代价规则 → N3b → N4b）
  → M2a 最小角色与远征保存、失败恢复
  → M2b 背包、材料、打造与两趟成长闭环
  → M3 眷族与队伍 → M4 跨角色与专业眷族
  → M5 内容与整体验收 → M7 独立终局切片

M0 用户试玩／美术认可 → 对应交互与素材验收，问题回流当前切片
M2–M4 数据稳定 → M6 联机与平台集成 → M7 多人验收
动作与武器小样 → 多队员可读性与内容生产
```

M1a 只保留事实状态，不依赖刷新时间、避战公式或死亡损失定案。M1b 使用可审阅的短流程规则验证原路返回与单次回城；M1c 再验证风险选择。M1 全部完成标准仍包含两类怪物、刷新和避战。M2 先建立保存边界与恢复检查，再增加可永久流转的物品，避免经济系统先产生无法可靠保存的收益。M6 可与 M5 交错推进；M7 的多人验收依赖 M6。

| 前置能力 | 下游依赖 | 当前缺口及接手注意 |
| --- | --- | --- |
| 历史楼层、已走路线及远征时间 | 返程、刷新显示、恢复远征 | N3a 已保留历史、已通过路线与 pending 遭遇，并分开到访、清理和领取；远征时间、刷新轮次与恢复仍待实现。`done` 暂用于下潜可达性，返程不能直接复用其禁止重复进入规则 |
| 稳定角色／远征／楼层／节点／内容标识 | 存档、掉落去重、任务与网络同步 | 节点已有远征 ID／楼层／局部 ID 组成的标识，同种子新远征也有独立身份；角色、内容版本与磁盘格式仍待设计，刷新后遭遇需要独立轮次 |
| 所有权与结算边界 | 背包、打造、任务、贡献、跨角色与联机 | 先定义个人角色、玩家共享眷族、主机世界及临时远征的回写位置；扣除和产出需共同成功，重复提交不能重复领奖 |
| 背包、装备与能力配置关联 | 锻造价值、职业成长、多成员准备 | 当前装备为只读展示；先验证打造出的装备实际改变可用行动或战斗表现 |
| 多成员回合与目标规则 | 眷族队友、合作联机、成熟阵容终局 | 当前仅一名己方和一名敌人，需扩展状态结构、目标与界面；不能只增加头像 |
| 动作规格、挂点与兼容样例 | 换装、武器替换、随机／自定义角色 | 当前武器和角色合并在站姿图；先验证一个身体与一种武器的完整动作，再扩充组合 |
| 平台适配、内容清单及版本校验 | Steam 联机、工坊、缺失资源恢复 | 选型与应用配置待确认；前期数据设计预留边界，接入时验证真实平台行为 |

## 开发计划与完成标准

以下编号用于跟踪，范围为基于现有设计的实施建议。M1a／N3a 已由 Codex 完成本轮实现与自动化验证；其他范围按下表及任务表推进。M0 持续记录技术回归和用户验收。承接任务时填写负责人、状态、关联 PR 与实际验证结果，不凭文档完成度估算游戏百分比。

| 编号／优先级 | 最小交付范围 | 前置 | 完成标准 |
| --- | --- | --- | --- |
| M0／持续 | 验收现有单次行动、目标选择、地图提示和战斗样张 | 当前 Demo | 试玩能理解行动消耗和不可用原因；分别登记手感结论、用户美术认可与技术验证，发现的问题落实到具体任务 |
| M1／当前 | 2–3 层返程切片、2 类怪物、刷新图标、交战／避战预览、最小回城结算 | 技术回归；M1a 无新增方向决策，M1b／M1c 分别收敛 D1–D3 | 按已走路线下潜和返程，图标进度与刷新判定一致，避战代价和实际扣除一致，回城收益只结算一次；状态设计支持后续保存 |
| M2／高 | 先最小保存与失败恢复，再接入一个目标配方、一件可打造武器、材料背包、补给交易、升级或转职前置、角色保存与继续旅程 | M1；D3–D4 | 连续两趟探索中，首趟所得可用于打造并改变次趟战斗；重启恢复成长与约定的远征状态；重复结算不重复发奖，保存失败有可恢复处理 |
| M3／中 | 一个入门远征眷族、加入任务、两名队友、编队、多成员战斗、一次队友成长与分级任务 | M2；队伍规模与操作规则确认 | 只有符合资格者可招募；参战后角色、队友和组织分别成长并正确保存；界面清楚展示每人行动与目标 |
| M4／中 | 两个角色档、至少两个眷族、转会、旧眷族积累保留；锻造与经商各验证一个小型样本，可拆分交付 | M3；D4–D5 | 新角色加入旧眷族可使用既有成果，个人成长独立；转会正确处理编队和借用物；非成员可用已约定基础服务，合法制作／成交推动服务方成长且不能重复刷贡献 |
| M5／后续 | 分批扩充职业、区域生态、精英／首领、怪物之宴、安全楼层、任务与经济；完善角色创建及成长表现 | M2–M4 已形成稳定闭环；动作小样通过；D6 | 扩充后仍能完成两趟探索并解释准备与收益的变化；验证长局时长、返程负担、职业差异、正式内容量与跨平台表现，逐批登记范围 |
| M6／后续 | Steam 接入、主机权威战斗与路线、角色带入带出、断线恢复；工坊以确认的一类内容做发布／订阅／加载闭环 | M2–M4 数据稳定；D7 | 多端结果一致，重复请求与重连无重复收益；缺失／不兼容扩展明确提示；macOS、Windows 分别验证。接入完成与正式发行分别验收 |
| M7／最后 | 独立终局入口、少量赐福、2–3 名首领、挑战保存与回写 | M5；D8；多人模式依赖 M6 | 使用成熟角色与队伍进入，临时赐福和永久成长分离，重复挑战有可应对变化，退出或结算不污染常规远征状态 |

首要体验门槛沿用整体方案：玩家在两趟连续探索后能说清第一次学到了什么、第二次准备改了什么、返程为什么打或躲、回城所得怎样改变了下次战斗。未达到时，先改善信息和成长动机，再增加内容数量。

## 持续维护规则

1. 项目负责人通过与 AI 对话维护整体方向和关键取舍；开发中的 AI 自行维护具体模块文档及本文。开工前阅读本文和相关模块，选择已有任务编号或补充任务，登记负责人、状态及当前阻塞；认领表示有人承接，完成状态需附证据。
2. 对话带来新的全局方向时，核对受影响模块并同步调整里程碑、依赖和待决策项。开发中途发现新的依赖、缺失工作或更合适的实施顺序时，AI 直接更新模块文档和本文，增补、拆分、合并、重排或删除任务，并说明对当前目标的影响；涉及整体方向与关键取舍时标为待决策，供项目负责人确定。具体数值或文案变化仅在影响范围、完成标准或优先级时同步到本文。
3. 代码、素材或测试变化时，在同一次提交／PR 更新模块的真实状态，并更新本文对应进度、任务、验收和最近核对日期。只有设计修改时，保持实现状态不变。项目负责人可以随时查看和反馈，AI 将反馈落实到相应文档与计划。
4. 将“原型已实现”推进为相应范围“已验收”时，记录覆盖的场景、测试结果及证据链接；美术分别记录用户认可、代理自检、引擎验收。未运行的检查明确写出。
5. 一个任务完成后收敛为当前进度和验收结论，移除失效阻塞与被替代计划；保留有用任务编号和 PR 链接即可，历史讨论使用 Git 追溯。
6. 接手者若发现实现超过本文记录，先补核对日期与证据再改状态；如暂时无法核实，标为待核验并说明缺什么。长期计划未承接时保持待开发，不自动视为进行中。

| 整体玩法／战斗规则 | 探索、成长、界面、动作、多成员／联机及对应计划 |

| 存档／平台／扩展 | 稳定标识、版本、缺失资源、联机恢复与 M6 |

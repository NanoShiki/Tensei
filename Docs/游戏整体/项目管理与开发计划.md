# 项目管理与开发计划

最近核对：2026-09-25。实现基线：`3a645c7`（本次整理前的 `main`）。本文是项目进展、开发顺序、依赖和接手信息的统一维护入口；具体玩法规则由各模块文档维护。

“实时”指每次相关设计、代码、素材或验收变化时，在同一次变更中更新本文。当前采用仓库内人工与 AI 协同维护，尚无自动扫描或后台同步机制。以下进度来自文档与代码核对；排期为建议顺序，尚无确认的人力、工期或发布日期。

## 项目目标与当前结论

已确定方向：日式西幻、非像素二维手绘、横版回合制地下城冒险。每人每回合默认行动一次；玩家长期培养角色、装备和眷族队友，每趟从第一层下潜，通过返程带回收获，再进行锻造、升级与转职。单人与联机沿用角色，Steam Listen Server 联机与创意工坊是产品目标。独立终局肉鸽在常规冒险及养成稳定后制作。

**当前处于战斗与逐层地图原型阶段。** 可运行主菜单、洛恩对哥布林的单人战斗、默认 30 层的下潜地图。城市往返与长期养成尚未形成可玩的完整循环。下一步建议先验收现有体验，再做 2–3 层返程切片。

30 层使用同一拓扑模板，仅部分节点类型随种子变化；这个参数不代表 30 层正式内容完成。探索、角色生命和药水仅在内存中延续；菜单的音量与全屏配置已经持久化，角色存档尚未实现。

## 依赖关系与实施边界

以下为建议实施顺序，箭头表示前置能力。平台与素材可开展小规模验证，正式集成仍需各自前置完成。

```text
现有战斗与下潜原型 → M0 体验验收
  → M1 返程切片（历史路线、刷新、避战、回城结算）
  → M2 养成闭环（背包、掉落、打造、装备、角色存档）
  → M3 眷族与队伍（任务、招募、多成员战斗、队友成长）
  → M4 跨角色与专业眷族（共享档案、转会、服务贡献）
  → M5 主游戏内容扩展与整体验收 → M7 独立终局切片

M1 起确定状态归属、稳定 ID、随机结果与奖励去重
  → M2 持久化落地 → M3/M4 共享成长 → M6 联机与平台集成
动作与部件小样 → 武器表现、多队员可读性 → 批量角色内容
内容标识与版本边界 → 存档兼容、联机内容校验、工坊加载
```

M6 可在 M2–M4 的数据与规则稳定后，与 M5 内容扩展交错推进；M7 的多人验收还依赖 M6。终局开发不作为常规养成闭环的前置。

| 前置能力 | 下游依赖 | 当前缺口及接手注意 |
| --- | --- | --- |
| 历史楼层、已走路线及远征时间 | 返程、刷新显示、恢复远征 | `floor_run.gd` 的 `generate_floor()` 会清空节点；当前 `done` 只表达本层一次完成。需区分到访、怪物刷新、唯一奖励领取状态 |
| 稳定角色／远征／楼层／节点／内容标识 | 存档、掉落去重、任务与网络同步 | 当前节点 ID 只在本层有效；已有能力 ID 可作为原型基础，完整命名空间与版本机制待设计 |
| 所有权与结算边界 | 背包、打造、任务、贡献、跨角色与联机 | 先定义个人角色、玩家共享眷族、主机世界及临时远征的回写位置；扣除和产出需共同成功，重复提交不能重复领奖 |
| 背包、装备与能力配置关联 | 锻造价值、职业成长、多成员准备 | 当前装备为只读展示；先验证打造出的装备实际改变可用行动或战斗表现 |
| 多成员回合与目标规则 | 眷族队友、合作联机、成熟阵容终局 | 当前仅一名己方和一名敌人，需扩展状态结构、目标与界面；不能只增加头像 |
| 动作规格、挂点与兼容样例 | 换装、武器替换、随机／自定义角色 | 当前武器和角色合并在站姿图；先验证一个身体与一种武器的完整动作，再扩充组合 |
| 平台适配、内容清单及版本校验 | Steam 联机、工坊、缺失资源恢复 | 选型与应用配置待确认；前期数据设计预留边界，接入时验证真实平台行为 |

## 开发计划与完成标准

以下编号用于跟踪，范围为基于现有设计的实施建议。各项当前均未登记开工；M0 是已有原型的补充验收。承接任务时填写负责人、状态、关联 PR 与实际验证结果，不凭文档完成度估算游戏百分比。

| 编号／优先级 | 最小交付范围 | 前置 | 完成标准 |
| --- | --- | --- | --- |
| M0／当前 | 验收现有单次行动、目标选择、地图提示和战斗样张 | 当前 Demo | 试玩能理解行动消耗和不可用原因；分别登记手感结论、用户美术认可与技术验证，发现的问题落实到具体任务 |
| M1／下一步 | 2–3 层返程切片、2 类怪物、刷新图标、交战／避战预览、最小回城结算 | M0；D1–D3 | 按已走路线下潜和返程，图标进度与刷新判定一致，避战代价和实际扣除一致，回城收益只结算一次；状态设计支持后续保存 |
| M2／高 | 一个目标配方、一件可打造武器、材料背包、补给交易、升级或转职前置、角色保存与继续旅程 | M1；D3–D4 | 连续两趟探索中，首趟所得可用于打造并改变次趟战斗；重启恢复成长与约定的远征状态；重复结算不重复发奖，保存失败有可恢复处理 |
| M3／中 | 一个入门远征眷族、加入任务、两名队友、编队、多成员战斗、一次队友成长与分级任务 | M2；队伍规模与操作规则确认 | 只有符合资格者可招募；参战后角色、队友和组织分别成长并正确保存；界面清楚展示每人行动与目标 |
| M4／中 | 两个角色档、至少两个眷族、转会、旧眷族积累保留；锻造与经商各验证一个小型样本，可拆分交付 | M3；D4–D5 | 新角色加入旧眷族可使用既有成果，个人成长独立；转会正确处理编队和借用物；非成员可用已约定基础服务，合法制作／成交推动服务方成长且不能重复刷贡献 |
| M5／后续 | 分批扩充职业、区域生态、精英／首领、怪物之宴、安全楼层、任务与经济；完善角色创建及成长表现 | M2–M4 已形成稳定闭环；动作小样通过；D6 | 扩充后仍能完成两趟探索并解释准备与收益的变化；验证长局时长、返程负担、职业差异、正式内容量与跨平台表现，逐批登记范围 |
| M6／后续 | Steam 接入、主机权威战斗与路线、角色带入带出、断线恢复；工坊以确认的一类内容做发布／订阅／加载闭环 | M2–M4 数据稳定；D7 | 多端结果一致，重复请求与重连无重复收益；缺失／不兼容扩展明确提示；macOS、Windows 分别验证。接入完成与正式发行分别验收 |
| M7／最后 | 独立终局入口、少量赐福、2–3 名首领、挑战保存与回写 | M5；D8；多人模式依赖 M6 | 使用成熟角色与队伍进入，临时赐福和永久成长分离，重复挑战有可应对变化，退出或结算不污染常规远征状态 |

首要体验门槛沿用整体方案：玩家在两趟连续探索后能说清第一次学到了什么、第二次准备改了什么、返程为什么打或躲、回城所得怎样改变了下次战斗。未达到时，先改善信息和成长动机，再增加内容数量。

当前主要风险：规则提案容易被误当成实现；30 层演示容易掩盖内容重复；返程和存档需要扩展现有状态结构；跨角色归属不清会造成奖励复制或成长丢失；动作量产未经样例验证。分别通过状态标记、小切片验收、状态归属设计、去重与恢复验证、动作小样控制。

1. 开工前阅读本文和相关模块，选择已有任务编号或补充任务，登记负责人、状态及当前阻塞；认领表示有人承接，完成状态需附证据。
2. 全局方向变化时，先核对受影响模块，再调整里程碑、依赖和待决策项。具体数值或文案变化仅在影响范围、完成标准或优先级时同步到本文。
3. 代码、素材或测试变化时，在同一次提交／PR 更新模块的真实状态，并更新本文对应进度、任务、验收和最近核对日期。只有设计修改时，保持实现状态不变。
4. 将“原型已实现”推进为相应范围“已验收”时，记录覆盖的场景、测试结果及证据链接；美术分别记录用户认可、代理自检、引擎验收。未运行的检查明确写出。
5. 一个任务完成后收敛为当前进度和验收结论，移除失效阻塞与被替代计划；保留有用任务编号和 PR 链接即可，历史讨论使用 Git 追溯。
6. 接手者若发现实现超过本文记录，先补核对日期与证据再改状态；如暂时无法核实，标为待核验并说明缺什么。长期计划未承接时保持待开发，不自动视为进行中。

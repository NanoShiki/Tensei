# 玩家主机联机

状态：设计草案，待实现。联机基于 Steam，采用 Listen Server，简称 LS，由一名玩家的主机承担服务器职责，同时参与游戏。平台接入和保存协议尚待实现验证。

## 合作体验方向

玩家共同进入地下城，通过职业、武器和道具配合进行战斗、探索与补给。联机应延续 [整体玩法设计](../游戏整体/整体玩法设计.md)中的城市与地下城连续体验。

玩家使用自己已培养的角色存档参与联机，可护送新手或在常规养成后共同挑战独立终局模式，并在之后继续单人探索。各玩家的眷族、队友和共享档案由其本人持有；同队玩家可以来自不同眷族。队伍人数、眷族队友席位、具体房间加入方式、中途加入及跨成长阶段的资格、数值和奖励适配待确认。护送设计需要保留成熟角色提供帮助的体验。

Steam 大厅、邀请与网络接入的技术候选见 [发行与创意工坊](../平台与扩展/发行与创意工坊.md)。平台服务、游戏主机权威和角色保存各有职责；Steam 接入仍需本项目实现同步与存档规则。

## 权威与一致性设计建议

玩家提交技能、目标、结束回合、路线选择和交易意图。主机服务器负责确认影响共享结果的状态变化，参与客户端获得一致结果。

| 状态 | 建议确认职责 |
| --- | --- |
| 战斗与怪物 | 主机确认当前行动者、行动次数、目标、骰点、物品消耗、伤害与死亡 |
| 掉落与背包 | 主机确认生成、归属、拾取与数量变更 |
| 打造与交易 | 主机确认资源消耗及对应产出 |
| 任务与职业 | 主机确认完成条件、领取与解锁 |
| 眷族与队友 | 主机确认任务贡献、招募资格、队友参与与经验；各玩家分别保存自己的眷族数据 |
| 终局肉鸽 | 主机生成或确认候选、选择结果、作用范围与有效期 |

这些是待实现的设计边界。网络同步频率、表现预测和存档技术留待技术细化。主机自身玩家的操作也应遵循相同的游戏规则。

## 个人、队伍与世界状态

设计时需要区分个人物品与职业、各玩家的眷族及队友、队伍共同目标，以及世界中的敌人、宝箱和商店状态。不同眷族的玩家可以组队；终局赐福应明确对个人、队伍或环境生效，跨眷族候选与队伍选择方式待确认。

多人同时拾取、交付或购买时，需要保证物品数量、任务奖励和库存一致。反复发送操作、断线重连或读取存档时，应避免重复消耗与重复发奖。

## 菜单与区域移动

建议联机中打开个人菜单时共享世界继续运行，详细输入与菜单约定见 [战斗操作与界面](../战斗与操作/战斗操作与界面.md)。是否支持全队暂停待确认。

个人返回城市、全队返回和队友分处不同楼层的规则待确认；其选择会影响世界运行范围与队伍交互。

## 保存与断线边界

一个角色存档对应一个角色，单人和联机使用同一角色成长；同一玩家多个角色共享其眷族档案。进入他人房间保留自身培养成果，合法获得的物品、职业和技能按个人归属回写角色，眷族任务贡献与队友经验回写该玩家的共享档案；具体奖励分配、保存时机、断线恢复和异常退出策略仍需设计。角色与世界进度边界见 [角色存档与长期成长](../角色系统/角色存档与长期成长.md)。

主机离开后采用结束房间、保存后恢复或主机迁移，需要后续选择。跨房间沿用角色的方向已确定，主机迁移尚待决策。

建议入房前校验角色版本、内容依赖及影响玩法的工坊扩展集合，主机与客户端就兼容性达成一致后加载角色。终局首领、效果和奖励随机结果由主机确认并同步；扩展不一致和重连后的恢复方式需明确提示。

## 待确认

- 人数上限、发现房间、邀请、加入与重连。
- 角色进度和世界进度的保存职责、回写协议，以及他人房间对个人世界解锁的影响。
- 死亡、复活、团灭、友伤与战利品分配。
- 主机离开、客户端断线和未完成交易的恢复规则。
- 联机延迟下的操作反馈，以及可信度与异常处理范围。

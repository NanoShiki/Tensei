# 玩家主机联机

状态：策划初稿，待实现。已确认采用 Listen Server，简称 LS，由一名玩家的主机承担服务器职责，同时参与游戏。

## 合作体验方向

玩家共同进入地下城，通过职业、武器和道具配合进行战斗、探索与补给。联机应延续 [整体玩法设计](../游戏整体/整体玩法设计.md)中的城市与地下城连续体验。

队伍人数、房间加入方式、平台联机服务及中途加入规则待确认。

## 权威与一致性设计建议

玩家提交移动、战斗、选择和交易意图。主机服务器负责确认影响共享结果的状态变化，参与客户端获得一致结果。

| 状态 | 建议确认职责 |
| --- | --- |
| 战斗与怪物 | 主机确认伤害、死亡和相关事件 |
| 掉落与背包 | 主机确认生成、归属、拾取与数量变更 |
| 打造与交易 | 主机确认资源消耗及对应产出 |
| 任务与职业 | 主机确认完成条件、领取与解锁 |
| 肉鸽与神明事件 | 主机生成或确认候选、选择结果、作用范围与有效期 |

这些是待实现的设计边界。网络同步频率、表现预测和存档技术留待技术细化。主机自身玩家的操作也应遵循相同的游戏规则。

## 个人、队伍与世界状态

设计时需要区分个人物品与职业、队伍共同目标，以及世界中的敌人、宝箱和商店状态。肉鸽效果应明确对个人、队伍或环境生效；眷族归属能否不同、队伍如何选择神明机会待确认。

多人同时拾取、交付或购买时，需要保证物品数量、任务奖励和库存一致。反复发送操作、断线重连或读取存档时，应避免重复消耗与重复发奖。

## 菜单与区域移动

建议联机中打开个人菜单时共享世界继续运行，详细输入与菜单约定见 [战斗操作与快捷交互](../战斗与操作/战斗操作与快捷交互.md)。是否支持全队暂停待确认。

个人返回城市、全队返回和队友分处不同楼层的规则待确认；其选择会影响世界运行范围与队伍交互。

## 保存与断线边界

正常往返保留物品的玩法已经确定。角色存档归属、进入他人世界后的收获保存、断线恢复和异常退出策略仍需设计。

主机离开后采用结束房间、保存后恢复或主机迁移，需要后续选择。当前没有承诺主机迁移或跨房间角色进度互通。

## 待确认

- 人数上限、发现房间、邀请、加入与重连。
- 角色进度与世界进度各自由谁保存。
- 死亡、复活、团灭、友伤与战利品分配。
- 主机离开、客户端断线和未完成交易的恢复规则。
- 联机延迟下的操作反馈，以及可信度与异常处理范围。

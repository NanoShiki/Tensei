# 角色存档与长期成长

状态：已实现“角色档案 → 多条存档记录”、远征手动保存、分级读取与继续旅程。基础经验／等级与个人委托已实现，四基础职业与共享眷族已接入，联机仍为设计草案。同一玩家的眷族成长跨角色保留、每次常规远征从第一层开始、持续培养和携带角色参与联机为已确定方向。

## 创建与继续游戏

玩家先创建角色档案，再在该角色下面保存多个时点的记录。角色档案拥有稳定身份；存档记录各自保存角色与远征的完整快照，读取某条恢复该时点，新增或覆盖一条不改写其他记录。同模板同名角色也有独立档案。当前以洛恩为模板，开始旅程可填写档案名称，首次成功保存后列入角色列表；预设选择、自定义和随机外观见 [角色创建与外观动画](角色创建与外观动画.md)，仍待实现。

地图“保存并退出”默认新增记录，可填写名称，也可选择本角色的已有记录并确认覆盖。主菜单“读取存档”先选角色，再选记录；“继续旅程”恢复最近一次成功保存或读取的记录。记录列表可滚动，显示名称、楼层、步数、方向与本地保存时间；同名角色显示短标识便于区分。本版不限制固定槽数，角色改名、自动存档及跨角色复制后续设计。每条记录旁可删除，确认后删除两代备份，无法撤销；取消保留原记录。损坏、不兼容和旧版记录也可显式删除。删除最后一条记录后角色从读取列表消失，当前运行中的角色仍可另存。

建议存档选择界面展示角色外观、名称、职业、当前眷族、成长程度、个人探索进度和最近保存时间，并标示所需扩展内容及兼容状态。一个玩家档案下可有多个角色存档；平台账号、玩家共享档案、角色标识、角色存档和联机房间分别建模。共享档案保存各眷族的设施、远征或城市服务贡献、任务成果、成员与赐福候选解锁，角色存档保存自身等级、装备、职业和当前眷族 ID。新角色加入已培养的眷族时读取共享成果，不复制旧角色的个人成长。详见 [眷族体系与成长](眷族体系与成长.md)。

## 长期培养

核心循环为：探索适合当前实力的楼层 → 获得武器、素材与成长机会 → 打造配装、转职并获得技能 → 提升战斗能力 → 挑战更深层。角色逐渐形成强大的长期培养成果，浅层仍可提供资源，玩家可选择稳妥积累或深入挑战。

永久获得的个人装备、职业和技能随角色存档延续；眷族设施、成员成长与解锁保存在玩家共享档案，转会后仍留在原眷族。终局挑战临时赐福只属于该次挑战状态。成长来源、技能学习条件和装备强度曲线待设计。

角色成长还可通过升级或转职等事件解锁新插画，预设角色初始拥有一张插画。解锁条件、收藏和存档字段建议统一维护在 [角色插画与成长解锁](角色插画与成长解锁.md)。

## 单人与联机共用角色

玩家可携带已培养的角色存档进入他人的联机房间，也可继续单人重复探索。高成长角色可护送新手，或与其他角色挑战终局地下城。联机中合法获得的角色物品和成长应回写到所选角色存档，具体奖励归属及保存协议待细化。

角色进度、玩家共享眷族进度、主机世界进度、常规远征状态与终局挑战状态需分别记录。常规远征保存已走路线、当前移动步数、节点刷新阈值、已生成怪物编队和奖励领取记录；终局挑战另存首领、赐福及本局奖励。存档或重连不能重新抽取同一节点的结果。角色当前归属、职业试炼资格与个人装备属于角色；眷族建设、队友与候选解锁属于玩家共享档案。加入他人房间时保留个人成长；他人世界的楼层开放、任务完成和首领击败是否推进自己的世界进度，需要逐项确定。队伍资格和内容兼容检查见 [玩家主机联机](../联机/玩家主机联机.md)。

## 当前保存与恢复边界

存读档窗口通过延迟场景切换退出，保证当前输入事件分发完成后再移除窗口视口；覆盖确认、读取与保存退出均覆盖这一生命周期边界。

地图与城市提供“保存并退出”，保存成功后返回主菜单；“继续旅程”读取完整安全点并恢复地图或城市。保留远征 ID、种子、楼层、深入／返回方向、当前位置、全部已生成节点、到访／清理／领取、路线、生命、金币、铁片、武器、两类药水、移动步数和刷新阈值。绕行也记录到访与路线，但保留在场怪物和原清理次数；库存随快照一起恢复。未知区域依原到访记录与当前位置重新显示，读取不计步、不重掷、不发放奖励。

本切片为手动安全点：活跃探索地图与城市整备可保存。战斗中、失败及回城摘要不能保存；关闭游戏、放弃返回菜单、死亡和回城均不自动覆盖记录，可读取已有手动记录。金币、材料和装备与地图一同保存为完整快照，读取旧记录恢复旧余额，回城不再次发奖；个人金币／任务奖励只在角色快照；眷族与两名队友另有跨记录共享成长账本，所有权与重试规则见 [眷族体系与成长](眷族体系与成长.md)。死亡后可读已有快照，正式损失规则待设计。新角色首次保存建立独立档案；覆盖确认仅替换选中的一条，取消保留原内容。战斗演示不写存档。

`Scripts/Core/save_library.gd` 管理目录 `user://expedition.profiles/<角色ID>/<记录ID>`，名称只用于显示，路径使用独立标识。每条记录通过 `expedition_save.gd` 保留 `.0.save` 与 `.1.save` 两代文件。先写临时文件、刷新并校验，再替换较旧一代；失败留在保存窗口显示原因。SHA-256 载荷包含完整快照及角色／记录元数据；读取校验结构、角色、目录归属、拓扑和运行时边界。单条最新代损坏时提示并使用该条另一完整代；损坏或不兼容的记录禁用读取／覆盖，其他记录仍可用。格式版本 `1`、内容版本 `demo-workshop-1`，兼容读取 `demo-factions-1`、`demo-depth-1`、`demo-team-1`、 `demo-patrol-1`、 `demo-enemies-1`、 `demo-jobs-1`、 `demo-party-1`、 `demo-avoid-1`、 `demo-growth-1`、`demo-boss-1`、`demo-city-1` 与 `demo-map-1`，缺失字段补零金币、零铁片、木剑及未完成首领目标。经验、等级、讨伐计数、五条任务状态、成员巡守计数、接取后的勘察深度、职业 ID 及匹配属性、眷族／玩家标识、两名队友编队、各自当前生命与含参战名单的待同步事件随角色快照保存；旧记录补剑士／未加入／单人／无待同步事件／未接取勘察／零勘察进度，共享档案成长独立读取。洛恩零生命但任一编队成员存活的安全点可保存／读取。旧记录补零经验、等级 1、未接取任务。任务材料和奖励没有外部账本，读取旧记录同时恢复当时资源和任务。角色 `captain_defeated` 随快照保存、跨远征保留；读取旧时点仍恢复该时点目标状态。旧已清理节点不追溯发放目标，后续再次战胜队长时记录。

目录列表从记录重建，`expedition.recent.cfg` 只记录继续入口，保存或显式读取后更新；索引丢失时选择最新可读记录。索引指向已删除或不存在记录时选择剩余最新可读记录，全部删除后禁用继续。若索引指向损坏记录，则禁用继续并提示，玩家可通过分级列表选择其他记录。当前无云存档、并发写入或跨平台验收保证。

版本保护以整条记录为单位：任一代版本不兼容时拒绝读取和覆盖，即使另一代可读，也不自动降级，以免旧程序回退进度并覆盖新版本文件。保存失败明确提示另存新记录，不要求删除原档。临时文件校验或提交失败、最近入口索引提交失败时尝试清理临时文件；目录权限阻止清理时可能残留，但不会作为有效存档读取。索引失败不撤销已写入的完整记录。

删除先提交 `.deleted` 标记，再清理两代文件；中断或清理失败时标记阻止旧代重新出现。删除标记无法提交时保留原档并显示失败。保存窗口删除已选记录后切回新增模式，读取窗口删除后立即刷新主菜单继续入口。验收：建立 A/B 两条，取消删除应保留，确认删除 B 只移除 B，继续应回到 A；删除最后一条后继续禁用。日志见 [运行日志与诊断](../项目规范/运行日志与诊断.md)。

兼容旧版 `user://expedition.0.save` 与 `.1.save`：以“洛恩 · 旧版角色／旧版安全点（只读）”列出，原文件不移动、不覆盖。读取后可在该角色下面另存多条新记录；每条记录内部两代备份与玩家可选记录分别管理。

验收：F5 → 开始旅程，填写“洛恩 A”进入城市，再从第一层出发。在入口保存“出发前”，继续后用 GM 通过战斗，再新增“战斗后”。主菜单读取存档，选“洛恩 A”，应见两条；分别读取应恢复对应节点与刷新数值。再建“洛恩 B”并保存，两个角色的记录应各自独立。在 A 内选择覆盖一条，取消应保持原内容；确认后只该条改变。读取 A 的较早记录后关闭重启，“继续旅程”应仍恢复较早记录。超过一屏的记录应能上下滚动。

`Tests/test_expedition_save.gd` 覆盖底层快照、校验与两代恢复；`Tests/test_save_library.gd` 覆盖角色隔离、多记录、单条覆盖、最近读取、旧档只读兼容、分级 UI、确认／取消及失败留图。可用 `TENSEI_LIBRARY_TEST_PHASE=write/read` 配合唯一的 `TENSEI_LIBRARY_TEST_PATH=user://test-library-<唯一标识>` 在两次独立进程验证多角色多记录重启。所有测试使用独立路径，保护玩家存档。

## 数据与保存建议

| 状态 | 建议保存内容与边界 |
| --- | --- |
| 角色身份与外观 | 角色标识、创建方式、外观配置、内容依赖 |
| 长期成长 | 职业与派生、已学技能、成长属性、个人任务与条件进度 |
| 持有物品 | 装备、背包、货币及已确定归属的容器引用 |
| 个人探索 | 已达成的个人探索记录；世界解锁规则单独判断 |
| 玩家共享眷族 | 各眷族的建设、远征与专业服务贡献、任务成果、队友或专业成员成长、赐福候选解锁及成员稳定 ID；跨该玩家的角色使用 |
| 当前归属 | 单个角色的眷族 ID 与个人贡献；转会时更新，旧眷族数据不删除 |
| 世界与会话 | 楼层、敌人、事件、随机结果及奖励领取记录，与角色数据区分 |
| 终局挑战 | 独立挑战 ID、随机种子、已选择的临时赐福、首领和结算状态 |
| 兼容信息 | 存档结构版本、游戏内容版本、启用的扩展及其版本 |

建议保存关键成长与奖励变更时采用完整事务、备份和可恢复写入，避免重复领取、部分扣除或存档损坏。转会同时更新角色归属、当前编队与借用物归还状态，不能只保存其中一部分；旧眷族仍保留。多人中由主机确认的结果附带可去重的记录，角色与队友经验分别回写各自所属档案；具体时机与重试、断线恢复协议待实现前设计。同一角色或共享眷族档案并发进入多个会话的处理也需约定。

扩展内容缺失或升级时，应先检查依赖并明确提示，保留原档和迁移备份。Steam 云存档是否启用、冲突处理和离线可用范围另行确认，平台范围见 [发行与创意工坊](../平台与扩展/发行与创意工坊.md)。

## 验证场景与待确认

后续原型应覆盖创建与读档、浅层积累后深入、角色转会并保留旧眷族、创建新角色加入旧眷族并招募已成长队友、单人角色加入他人房间并带回成长、退出后继续单人、重复保存去重、断线恢复与扩展缺失提示。

待确认：手动与自动保存时机、死亡和团灭损失、世界进度归属、共享档案绑定本地档案还是平台账号、存档槽上限、跨版本迁移、异常退出与修改存档的处理策略。长期培养不预设死亡清档或无限数值成长。

关联：[眷族体系与成长](眷族体系与成长.md)、[职业与派生成长](../角色成长/职业与派生成长.md)、[背包与物品流转](../装备与物品/背包与物品流转.md)、[终局肉鸽机制](../肉鸽系统/终局肉鸽机制.md)。

节点敌人内容 ID 随快照保存，旧记录补普通哥布林／队长，未注册内容或非战斗节点携敌人拒绝读取；当前新类型规则见探索文档。

旧记录补未接取成员巡守与零编队目标，任务部分／领奖状态按个人快照恢复；共享组织等级／卫士经验独立保持。计数严格 0–5，已领取须五场，成员任务须晨行归属。

当前归属支持晨行与炉心；炉心记录保留暂停的晨行巡守，拒绝携带晨行队友。实际锻造后未加入的角色也绑定玩家身份并携带 `forge_pending` 待同步贡献；旧记录补空队列，异角色事件拒绝读取。所有已绑定身份的读档均实时核对共享玩家身份，失败不改变当前旅程或最近记录。共享 `demo-familia-3` 在内存迁移两版旧晨行档案，读取保持原文件字节；转会与兼容规则见眷族文档。

# 角色存档与长期成长

状态：设计草案，待实现。一档一角色、同一玩家的眷族成长跨角色保留、每次常规远征从第一层开始、持续培养和携带角色参与联机为已确定方向；保存时机、数据结构和异常恢复为待细化方案。

## 创建与继续游戏

玩家创建一个存档，为其选择一个预设、自定义或随机角色。一个存档对应一个角色，之后保存与读取该存档，继续培养同一角色。外观入口与装配规则见 [角色创建与外观动画](角色创建与外观动画.md)。存档槽数量、复制和删除操作待设计。

建议存档选择界面展示角色外观、名称、职业、当前眷族、成长程度、个人探索进度和最近保存时间，并标示所需扩展内容及兼容状态。一个玩家档案下可有多个角色存档；平台账号、玩家共享档案、角色标识、角色存档和联机房间分别建模。共享档案保存各眷族的设施、远征或城市服务贡献、任务成果、成员与赐福候选解锁，角色存档保存自身等级、装备、职业和当前眷族 ID。新角色加入已培养的眷族时读取共享成果，不复制旧角色的个人成长。详见 [眷族体系与成长](眷族体系与成长.md)。

## 长期培养

核心循环为：探索适合当前实力的楼层 → 获得武器、素材与成长机会 → 打造配装、转职并获得技能 → 提升战斗能力 → 挑战更深层。角色逐渐形成强大的长期培养成果，浅层仍可提供资源，玩家可选择稳妥积累或深入挑战。

永久获得的个人装备、职业和技能随角色存档延续；眷族设施、成员成长与解锁保存在玩家共享档案，转会后仍留在原眷族。终局挑战临时赐福只属于该次挑战状态。成长来源、技能学习条件和装备强度曲线待设计。

角色成长还可通过升级或转职等事件解锁新插画，预设角色初始拥有一张插画。解锁条件、收藏和存档字段建议统一维护在 [角色插画与成长解锁](角色插画与成长解锁.md)。

## 单人与联机共用角色

玩家可携带已培养的角色存档进入他人的联机房间，也可继续单人重复探索。高成长角色可护送新手，或与其他角色挑战终局地下城。联机中合法获得的角色物品和成长应回写到所选角色存档，具体奖励归属及保存协议待细化。

角色进度、玩家共享眷族进度、主机世界进度、常规远征状态与终局挑战状态需分别记录。常规远征保存已走路线、当前远征时间、节点刷新阈值、已生成怪物编队和奖励领取记录；终局挑战另存首领、赐福及本局奖励。存档或重连不能重新抽取同一节点的结果。角色当前归属、职业试炼资格与个人装备属于角色；眷族建设、队友与候选解锁属于玩家共享档案。加入他人房间时保留个人成长；他人世界的楼层开放、任务完成和首领击败是否推进自己的世界进度，需要逐项确定。队伍资格和内容兼容检查见 [玩家主机联机](../联机/玩家主机联机.md)。

## 数据与保存建议

| 状态 | 建议保存内容与边界 |
| --- | --- |
| 角色身份与外观 | 角色标识、创建方式、外观配置、内容依赖 |
| 长期成长 | 职业与派生、已学技能、成长属性、个人任务与条件进度 |
| 持有物品 | 装备、背包、货币及已确定归属的容器引用 |
| 个人探索 | 已达成的个人探索记录；世界解锁规则单独判断 |
| 玩家共享眷族 | 各眷族的建设、远征与专业服务贡献、任务成果、队友或专业成员成长、赐福候选解锁及成员稳定 ID；跨该玩家的角色使用 |
| 当前归属 | 单个角色的眷族 ID 与个人贡献；转会时更新，旧眷族数据不删除 |
| 世界与会话 | 楼层、敌人、事件、随机结果及奖励领取记录，与角色数据区分 |
| 终局挑战 | 独立挑战 ID、随机种子、已选择的临时赐福、首领和结算状态 |
| 兼容信息 | 存档结构版本、游戏内容版本、启用的扩展及其版本 |

建议保存关键成长与奖励变更时采用完整事务、备份和可恢复写入，避免重复领取、部分扣除或存档损坏。转会同时更新角色归属、当前编队与借用物归还状态，不能只保存其中一部分；旧眷族仍保留。多人中由主机确认的结果附带可去重的记录，角色与队友经验分别回写各自所属档案；具体时机与重试、断线恢复协议待实现前设计。同一角色或共享眷族档案并发进入多个会话的处理也需约定。

扩展内容缺失或升级时，应先检查依赖并明确提示，保留原档和迁移备份。Steam 云存档是否启用、冲突处理和离线可用范围另行确认，平台范围见 [发行与创意工坊](../平台与扩展/发行与创意工坊.md)。

## 验证场景与待确认

后续原型应覆盖创建与读档、浅层积累后深入、角色转会并保留旧眷族、创建新角色加入旧眷族并招募已成长队友、单人角色加入他人房间并带回成长、退出后继续单人、重复保存去重、断线恢复与扩展缺失提示。

待确认：手动与自动保存时机、死亡和团灭损失、世界进度归属、共享档案绑定本地档案还是平台账号、存档槽上限、跨版本迁移、异常退出与修改存档的处理策略。长期培养不预设死亡清档或无限数值成长。

# 角色创建与外观动画

状态：设计草案，待实现。三种角色创建入口、二维部件组合与武器驱动动作选择为已确定方向；本文的分层结构、兼容规则、回退顺序和工具选择属于技术建议，尚未通过运行样例验证。

## 目标与角色创建

预设人物按一人一文档维护在 `Docs/人物/<姓名>/`。第一位预设角色为 [红发剑士](../人物/洛恩/人物设计.md)，其已确认造型、素材与背景提案在该文档维护。

角色在完成二维捏人后，应正确播放多方向移动、攻击、受击等动作，并支持外观和武器替换。局内采用非像素手绘表现，制作约束见 [美术风格与素材制作](../美术/美术风格与素材制作.md)。

已确定提供三种入口：

预设角色在选择时展示初始插画，后续可随成长解锁新插画；随机、自定义角色的插画适配方式待定，见 [角色插画与成长解锁](角色插画与成长解锁.md)。

三种入口用于创建角色存档，一个存档对应一个角色。之后读取同一存档延续培养，并可用于单人与联机，见 [角色存档与长期成长](角色存档与长期成长.md)。

| 入口 | 体验 |
| --- | --- |
| 预设角色 | 选择已经配置好的角色进入游戏 |
| 随机角色 | 随机得到包含种族、发型、身材等特征的角色 |
| 玩家自定义 | 玩家选择种族、身体、头发等外观选项 |

建议三种入口共用一份外观配置，记录身体模板、种族外观、部件标识和颜色。随机入口在兼容范围内组合选项；从固定预设中抽取的入口形式、随机权重与锁定选项待细化。角色选择参考《以撒》的预设入口体验，角色能力与职业、种族之间的关系另行设计。

初期建议使用几种固定身体模板，颜色通过遮罩调整，发型、耳朵和服饰通过部件替换。连续身高、胖瘦、肩宽和五官滑条会影响轮廓、连接点及装备适配，其范围待验证。头像与局内外观应保持一致的角色特征，头像的生成或组装方式待定。

## 组合结构建议

| 层次 | 负责内容 | 示例 |
| --- | --- | --- |
| 外观配置 | 保存玩家选择，供预设、随机和自定义共同使用 | 精灵耳朵、纤细模板、长发、发色 |
| 身体与部件资产 | 提供骨架、图片、方向、连接点、变形和遮挡规则 | 头发挂在头部，袖子跟随手臂，剑连接手掌 |
| 动作系统 | 根据状态、武器与方向选择动作并统一驱动部件 | 奔跑、单手剑攻击、特殊武器攻击、长发摆动 |

“部位—资产—动画”作为内容组织思路保留。每个部位可提供动画数据，每件武器需关联适用动作配置；多个资产可以引用同一动作集。身体动作由兼容模板共享，长发、披风、尾巴等按需增加专属摆动或姿势图。

二维骨架只在平面中控制图片的位移、旋转和变形。正面、侧面和背面需准备对应素材及方向动作；方向切换同时处理图片、姿势和前后遮挡。

## 部件资产约定建议

- 每个部件记录适用身体模板、朝向集合、挂点、枢轴、图片或网格、颜色遮罩、遮挡规则，以及可选的专属动画与姿势替换。
- 眼睛、眉毛和耳朵跟随头部；短发可使用少量变形；长发、披风和尾巴增加附属运动；袖子、裤腿与对应肢体共同运动。
- 一个可选项允许拆成多个渲染部件，例如长发包含头前和头后部分。手掌、握柄和武器需要共同校验位置；身体转向时调整绘制顺序。
- 关节和遮挡区域需要补全图片，避免抬手或摆腿时露出空缺。相同模板统一基础姿势、比例和连接位置。
- 非对称发型、持械手、盾牌和服装图案需要专门检查镜像规则。明显不同的身体比例、特殊腿型、翅膀等需提供适配模板或专属动作。

## 武器与动作选择

已确定：装备武器参与选择角色播放的动作。普通武器复用对应类型的基础动作集，特殊武器可提供专属动作。更换外观部件后，这些动作仍须在兼容身体上正确播放。武器的获得与打造见 [武器掉落与打造](../装备与物品/武器掉落与打造.md)。

建议将武器动作配置关联到武器定义，记录动作类型、握持挂点与偏移、兼容身体模板，以及可选的专属动作覆盖。单手剑、双手重武器、长枪、弓等可各自提供动作集，具体分类待战斗设计确定。

建议按“当前动作 + 装备武器 + 身体模板 + 朝向”解析资源，逐项选择：

1. 该武器针对当前动作提供的兼容专属覆盖。
2. 该武器类型对应的兼容基础动作。
3. 明确登记的兼容通用动作；缺失时报告资源问题，并按已验证规则限制该组合。

特殊武器可以只覆盖某次攻击，也可覆盖完整持械动作组，其余动作继续使用基础配置。剑刃发光、弓弦拉动等武器自身的动画与角色动作共同播放。武器类型和身体模板的兼容性需在资源检查与装备时校验。

建议示例：普通铁剑和钢剑共用单手剑攻击，换装只替换剑的图像及握持配置；特殊雷剑覆盖重击动作，并在指定阶段驱动剑身特效、手臂和躯干姿势。武器名称和具体招式均为示例。

## 统一播放与战斗衔接

建议由角色动作控制器统一管理状态、方向、时间进度和动作切换。身体、部件序列帧、附属动画及武器动画从同一动作上下文取样，按需要配置阶段偏移和混合，避免各部件独立计时导致错拍。

移动方向、鼠标瞄准方向和视觉朝向分别记录。WASD 支持平面移动，视觉方向数可先验证四向再扩展八向；移动中攻击时朝向优先级、上半身与下半身混合范围待原型确定。不同方向切换需保持动作阶段连续，并更新遮挡和挂点。

攻击动作需共同描述准备、命中窗口和收招等阶段，具体判定由战斗逻辑维护，动画、音效和特效读取一致的动作阶段。取消、受击打断及换武器时，统一清理旧动作的挂点覆盖、特效和事件，防止重复命中或残留表现。换武器生效时机、攻速变化和中途切换的过渡规则待验证。

Listen Server 联机建议同步外观配置标识、武器、动作状态和必要时间信息，由各端使用相同资源播放；主机负责权威战斗结果。预测、校正和具体同步格式待联机方案细化，见 [玩家主机联机](../联机/玩家主机联机.md)。

## 完整播放示例

玩家选择长发精灵并装备普通剑 → 装配兼容身体、耳朵、长发与武器 → 向右移动时共享奔跑动作驱动肢体，头发增加摆动 → 向上转身时切换背面素材与遮挡 → 攻击时解析单手剑动作，手掌与剑保持连接 → 换成特殊剑后，在规则允许的时机启用专属动作覆盖。

## 制作与验证建议

建议采用共享二维骨骼动作，结合部件专属动画、关键姿势替换与补帧。分层序列帧也可参与组合，其制作量随部件、方向、动作和帧数增加；序列帧与骨骼动画均需服从统一进度。

生图主要承担各方向外观、部件、武器与关键姿势图片。后续需要完成分层补全、连接点对齐、网格或骨骼绑定、动画编排及引擎检查。完整动画集和批量生产效率尚待验证。

工具候选包括 Godot 原生二维骨骼与动画工具，以及 Spine 的皮肤组合和绑定工具；最终选型、版本兼容、授权和导入方式待原型决定。

首轮样例范围见 [美术风格与素材制作](../美术/美术风格与素材制作.md)。需覆盖全部样例外观组合，检查方向切换、握持、接缝、遮挡、帧间一致性、普通动作复用、特殊动作覆盖、资源缺失回退和动作打断。连贯性需通过实际播放确认。

参考：[Godot 二维骨骼](https://docs.godotengine.org/en/stable/tutorials/animation/2d_skeletons.html)、[Spine 外观组合示例](https://esotericsoftware.com/spine-examples-mix-and-match)。这些工具资料支持方案评估；《Jotun》《33 Immortals》的实际流程说明见美术文档。

# 版本控制与文件提交

本规范说明哪些文件纳入 Git 仓库、哪些由本机生成，重点约定 Godot 生成的 `.uid` 与 `.import` 文件的处理方式。开发者与 AI 代理在提交前按本文核对改动范围。

## 提交范围

必须提交：

- 场景 `.tscn`、脚本 `.gd`、着色器 `.gdshader`、资源 `.tres` 等项目内容文件。
- 脚本和着色器旁的同名 `.uid` 文件，例如 `main_menu.gd` 对应 `main_menu.gd.uid`。
- 图片、音频等导入资源的原始文件及其同名 `.import` 文件，例如 `icon.svg` 对应 `icon.svg.import`。
- `project.godot`、`.gitignore`、`.gitattributes` 等仓库与项目配置文件。

不提交：

- `.godot/`：本机导入缓存与编辑器状态，已由 `.gitignore` 忽略，删除后可重新导入生成。
- 导出产物，例如可执行文件与 `.pck`。
- 操作系统元数据 `.DS_Store`、`Thumbs.db`、`Desktop.ini`。

## `.uid` 文件的作用

Godot 从 4.4 起为无法在自身文件内记录标识符的资源生成同名 `.uid` 文件，内容是一行形如 `uid://b18od6mcqul4n` 的标识符。本项目中脚本和着色器属于这类文件。

- 场景和资源引用脚本时记录 UID，文件重命名或移动后引用仍然有效。
- `.tscn` 和 `.tres` 把 UID 写在文件头部，图片、音频等导入资源的 UID 记录在 `.import` 文件中，这两类文件不生成 `.uid`。
- `.uid` 缺失时编辑器在下次导入项目时生成新的标识符。各台机器分别生成会得到不同的值，已经按 UID 建立的引用随之失效，因此 `.uid` 必须随脚本一起提交。
- `.uid` 的内容由引擎维护，手工编辑属于错误操作。
- 复制脚本文件时删除一并复制的 `.uid`，让引擎为新文件生成独立的标识符，避免两个文件声明同一个 UID。

## 新增文件后的提交步骤

1. 在 Godot 中打开项目并等待导入完成，或执行 `godot --headless --path . --import` 生成 `.uid` 与 `.import`。
2. 执行 `git status`，确认每个新增脚本旁出现 `.uid`，每个新增导入资源旁出现 `.import`。
3. 把源文件与其 `.uid`、`.import` 放在同一次提交中，保持仓库内同类文件状态一致。
4. 删除脚本或资源时，同时删除对应的 `.uid` 和 `.import`。

## 其他仓库约定

- 文件名与代码、场景中引用的大小写保持一致，避免 macOS 与 Windows 之间出现差异。
- 文本换行由 `.gitattributes` 统一为 LF。
- 路径使用 `res://` 和 `user://`，避免写死操作系统绝对路径。
- 多人开发时尽量避免同时编辑同一个场景。

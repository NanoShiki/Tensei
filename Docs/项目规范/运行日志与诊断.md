# 运行日志与诊断

状态：当前 Demo 的业务事件、引擎错误持久化与日志规则检查已接入。日志用于还原行为和检查已编码的规则；完整视觉体验、所有玩法正确性仍需测试与人工验收。

## 获取一次试玩日志

游戏中打开 GM → 打开日志目录。默认位置为 `user://logs`，Windows 通常对应 `%APPDATA%/Godot/app_userdata/Project Tensei/logs`；启动控制台也会打印实际路径。反馈时说明操作和大致时间，并提供本次 `events-*.jsonl` 与对应 `godot.log`。日志只存本地，不自动上传，不记录账号凭据或存档名称。

- `events-<会话ID>-<分段>.jsonl`：每行独立 JSON，包含 UTC 时间、启动后毫秒、会话 ID、递增序号、级别、模块、事件、角色／存档／远征标识与事件数据。单文件达到约 2 MiB 后轮转，最多保留 10 个文件；单条事件不截断，因此文件可略超阈值。测试可用 `TENSEI_LOG_DIR` 指定独立目录。
- `godot.log` 及其轮转文件：Godot 原生输出，保留引擎和脚本错误、警告及调用栈；最多 5 个轮转日志。`TENSEI_LOG_DIR` 只影响业务日志，自动测试可另用 Godot `--log-file` 隔离引擎日志。
- 每条业务事件立即刷新；写入失败通过引擎报错一次并停止业务日志写入，游戏继续运行。磁盘或权限异常可能阻止旧文件清理；正常退出有 `session.end`，强制结束或崩溃可能没有结束事件。

## 当前记录范围

| 模块 | 记录 |
| --- | --- |
| 会话与场景 | 引擎版本、Demo 内容标识、平台、创建角色、读取后的完整运行状态、场景切换结果、正常退出 |
| 探索 | 深入／返回、移动与跨层、战斗结算、入城与再出发；操作前后楼层／节点／阶段／步数／角色资源／已清理怪物刷新状态，远征种子 |
| 遭遇绕行 | 预览、选择与取消的节点／角色状态；成功绕行的完整目标节点与角色／探索状态；移动日志含 avoid 标志；规则工具检查道具消耗、保留怪物及无胜利／战利品 |
| 战斗 | 开始种子、先攻顺序、技能／道具／敌人行动／结束回合／GM 秒杀前后状态；攻击骰点、加值、AC、命中与伤害 |
| 背包 | 打开及探索用药的结果、拒绝原因、恢复量、前后生命／库存／步数／刷新状态 |
| 阶段目标 | 队长胜利、是否首次完成；战斗前后状态含队长标志与蓄力状态，角色快照含目标进度 |
| 委托与成长 | 接取／领奖的任务标识、成功／拒绝原因、前后角色与探索状态，含经验、等级与任务状态 |
| 城市 | 休整、购药、打造的输入、成功或拒绝及前后资源 |
| 存档 | 新增／覆盖／显式读取／删除结果、记录标识与失败原因，保存时状态；恢复另一代的提示随读取结果保留 |
| GM | 执行命令与结果，秒杀仍经正常战斗结算 |

`INFO` 为正常事件，`WARN` 包含被拒绝的操作，`ERROR` 为保存／删除／场景切换等失败。错误注入测试会有预期 ERROR，须结合测试场景判断；未出现 ERROR 不能单独证明玩法全部正确。日志包含内部探索信息，仅用于开发诊断。

## 统一回归与证据目录

`python Tools/run_demo_checks.py --godot "控制台引擎路径"` 从独立临时目录记录每组控制台输出、引擎日志及 JSONL，导入资源后运行全部 `Tests/test_*.gd` 和 Python 测试。每组默认 60 秒超时，导入默认 180 秒，可用 `--import-timeout` 单独调整；非零退出、脚本／引擎 ERROR、缺少测试完成标记判为失败。`--tests` 接收脚本文件名去掉 `.gd` 的名称，`--timeout` 可调整单进程期限。环境中的 TENSEI 截图／重启测试标志不传给此运行，防止意外改变场景。

城市、背包、阶段队长、委托和遭遇选择正常流程按实际存在的专项自动调用日志规则检查，要求有业务日志及正常会话结束；报告逐项列出 `log_rules_checked` 和异常。底层保存、删除及战斗边界测试包含预期失败／人为构造状态，其业务日志留作证据，由对应断言判断，不自动按普通试玩日志判错。每组退出与引擎错误仍检查。底层安全点与多角色库另以同一唯一测试路径分别启动写入、读取两个进程，验证真实重启恢复；报告 restart 项独立列出，不继承外部指定的玩家路径。工具的判定测试覆盖引擎报错但退出码为零、无完成标记及进程失败，避免假通过。

测试使用自身独立存档路径。结果目录位于系统临时目录 `tensei-demo-checks-*`，`summary.json` 汇总退出码、耗时、日志检查与证据路径；本机缓存无需提交。Windows 当前构建已运行，macOS 运行及实际图形体验仍待验收。工具不会调用 Git 推送或合并。

## 检查工具与开发约定

`python Tools/check_logs.py "日志目录或单个 JSONL 文件"` 汇总事件和会话，检查格式、序号、ERROR、移动一步计时、刷新倒计时、胜利资源、交易扣款、绕行消耗及无奖励、背包用药消耗及不计步、再次出发的资源延续、委托一次性奖励／材料扣除／成长属性一致性；出现异常退出码为 1。当前运行中会话或强制退出会列为 incomplete，需结合时间及引擎日志判断。轮转清理后的早期事件不在检查范围，工具无法重建丢失事件，也不替代完整回放。

新增或修改有状态玩法时，接入 `Scripts/Core/game_log.gd`，至少记录操作、输入、结果、必要的前后状态与失败原因；给新规则增加对应测试，适合从日志判断的约束加入检查工具。禁止逐帧、每次界面刷新重复打印；禁止写入令牌、账号凭据、完整个人路径或完整存档二进制。未来联机增加房间和请求标识，当前仅覆盖单人主线程 Demo。

验收：F5 玩一次探索、战斗、回城打造及保存读取；GM 打开日志目录，确认新会话文件包含对应事件，运行检查工具查看统计和异常。引擎错误单独查 `godot.log`。`Tests/test_logs_delete.gd` 覆盖日志 JSON、顺序和容量轮转；城市循环实际日志已由检查工具核对。

# 人物设计与素材规范

状态：人物设计与原画风格已通过洛恩样张确认。洛恩是预设角色标准模板；横版单帧姿态已用于 Demo，完整动画待制作。

## 人物设计内容

每个角色在 `Docs/人物/<姓名>/人物设计.md` 维护一个完整文档，包含定位、性格与行为、背景、外貌服饰、参考范围、战斗表现、成长、台词、素材清单与实际进度。完整保留用户的要求和参考意图，明确提案与已确认内容。

人物应具备日常性格、认真投入时的表现及成长愿望。原画通过行动、神态、视线和情境展现人物精神。依据主题采用近景、特写或动态构图，使读者能看出角色正在做什么、为什么值得关注。洛恩的初始原画表现认真练剑时的坚定眼神；其开朗性格通过日常与表情设定表达。

## 用户确认顺序

1. 阅读相关人物与模块文档，规范化整理需求，提出一张人物设计稿，包含身份基准与必要视图。
2. **用户认可设计稿后，再生成原画及其他素材。** 用户要求调整时先修订设计稿，后续图片使用最新确认稿作为参考。
3. 原画确认人物表现、构图、场景细节与光影。根据用户反馈迭代，取得认可后建立风格基准，再展开配套制作。
4. 新转职造型、服装或重要外貌变更先按设计稿流程确认。成长插画可在已确认造型内表现能力与精神变化。
5. 记录每项的用户确认与技术验收状态，代理自检和用户认可分别登记。

## 已确认美术标准

- 纯二维、非像素的二次元插画表现，局内资产兼顾横版战斗表现与信息可读性。
- 清楚而干净的线条、稳定色块和连续的大块明暗。控制噪点、颗粒、杂色边缘、碎高光及斑驳光影。
- 场景具有适中的细节密度，通过前中后景、建筑结构与少量有意义的道具交代故事。大面积墙面、地面和树冠保持视觉秩序。
- 细节围绕主体分配，人物脸、眼神和动作形成重点，背景降低对比。树叶、砖块、绳纹等重复元素采用概括表达。
- 光源方向统一，阴影形状完整，材质细节克制。画面放大检查杂色，缩小检查主体与层次。
- 洛恩的稚气脸型、红发、琥珀眼、米白短袖、深蓝练功服、布质束腰和木剑构成当前身份基准。其他角色遵循同一制作标准，并拥有独立造型。

## 目录与交付

人物文档与素材集中到 `Docs/人物/<姓名>/`，图片与制作附件放在 `素材/`。洛恩见 [人物设计](洛恩/人物设计.md)。图片在这里承担设定与制作参考用途。通过引擎验收的战斗素材进入运行时目录 `Assets/Characters/<角色>/`，保持单一副本，目录约定见 [版本控制与文件提交](../项目规范/版本控制与文件提交.md)。

清单记录尺寸、真实 alpha、帧数、哈希、参考和状态。审批通过的设计稿与原画保留准确来源。弃用候选不混入当前标准包。

## 战斗素材验收

横版战斗素材的具体尺寸、帧数与锚点规则随回合制战斗原型确定，见 [回合制战斗](../战斗系统/回合制战斗.md) 与 [美术风格与素材制作](../美术/美术风格与素材制作.md)。验收至少检查主体完整、比例一致、轮廓无漂移、动作衔接、锚点稳定，以及在实际战斗画面尺寸下的可读性。

捏脸与换装采用身体模板、部件与共享动作的组合方案；部件需要补全遮挡区域、统一挂点与时间轴。武器类型选择通用动作，特殊武器提供动作覆盖。相关设计见 [角色创建与外观动画](../角色系统/角色创建与外观动画.md)。

图片生成、逐帧预览、透明处理、部件拆分、绑定和 Godot 验收分别记录进度。仅完成源图时标记为设计参考，保持真实的完成边界。

独立角色、动作及可替换部件素材应主动移除背景并交付真实透明 PNG，检查 Alpha、主体不透明度及深浅底边缘。人物设定稿与情境原画保留必要底色和场景。残留光晕、白边或杂色时登记未通过，继续修正后方可进入运行时资产。

# 人物设计与素材规范

状态：人物设计与原画风格已通过洛恩样张确认。洛恩是预设角色标准模板；动作与可换装资产仍需完成工程验证。

## 人物设计内容

每个角色在 `Docs/人物/<姓名>/人物设计.md` 维护一个完整文档，包含定位、性格与行为、背景、外貌服饰、参考范围、战斗表现、成长、台词、素材清单与实际进度。完整保留用户的要求和参考意图，明确提案与已确认内容。

人物应具备日常性格、认真投入时的表现及成长愿望。原画通过行动、神态、视线和情境展现人物精神。依据主题采用近景、特写或动态构图，使读者能看出角色正在做什么、为什么值得关注。洛恩的初始原画表现认真练剑时的坚定眼神；其开朗性格通过日常与表情设定表达。

## 用户确认顺序

1. 阅读相关人物与模块文档，规范化整理需求，提出一张人物设计稿，包含身份基准与必要视图。
2. **用户认可设计稿后，再生成原画及其他素材。** 用户要求调整时先修订设计稿，后续图片使用最新确认稿作为参考。
3. 原画确认人物表现、构图、场景细节与光影。根据用户反馈迭代，取得认可后建立风格基准，再展开配套制作。
4. 新转职造型、服装或重要外貌变更先按设计稿流程确认。成长插画可在已确认造型内表现能力与精神变化。
5. 记录每项的用户确认与技术验收状态，代理自检和用户认可分别登记。

## 已确认美术标准

- 纯二维、非像素的二次元插画表现，局内资产兼顾俯视角与操作可读性。
- 清楚而干净的线条、稳定色块和连续的大块明暗。控制噪点、颗粒、杂色边缘、碎高光及斑驳光影。
- 场景具有适中的细节密度，通过前中后景、建筑结构与少量有意义的道具交代故事。大面积墙面、地面和树冠保持视觉秩序。
- 细节围绕主体分配，人物脸、眼神和动作形成重点，背景降低对比。树叶、砖块、绳纹等重复元素采用概括表达。
- 光源方向统一，阴影形状完整，材质细节克制。画面放大检查杂色，缩小检查主体与层次。
- 洛恩的稚气脸型、红发、琥珀眼、米白短袖、深蓝练功服、布质束腰和木剑构成当前身份基准。其他角色遵循同一制作标准，并拥有独立造型。

每位角色交付八张 PNG 源图。动作素材仅保留当前透明版本，已否决的动作图删除。相同阶段采用相同数量，扩展时统一升级包规格。

| 02 | 表情设定 | 平静、开心、困惑、认真、受惊、害羞，共六种 |

## 目录与交付

人物文档与素材集中到 `Docs/人物/<姓名>/`，图片与制作附件放在 `素材/`。洛恩见 [人物设计](洛恩/人物设计.md)。图片在这里承担设定与动作参考用途。通过引擎验收的透明部件、骨骼与动画资源再进入运行时资源目录。

运行时资源目录为 `Assets/Characters/<角色>/`。洛恩的 07-俯视行走与 08-俯视跑步已通过引擎播放验收并移入该目录，素材清单记录其运行时路径；其余素材仍在 `Docs/人物/洛恩/素材/` 承担设定用途。目录约定见 [版本控制与文件提交](../项目规范/版本控制与文件提交.md)。

清单记录尺寸、真实 alpha、网格、实际朝向、帧数、建议预览速度、哈希、参考和状态。审批通过的设计稿与原画保留准确来源。弃用候选不混入当前标准包。

## 动画与换装验收

检查方向顺序、完整网格、格子越界、头身比例、轮廓漂移、足底锚点、循环衔接、握持和遮挡。按实际图像登记方向，发现混向必须修正才能进入游戏。

整身动作图用于评估姿态。捏脸与换装仍采用身体模板、部件、朝向及共享动作的组合方案；部件需要补全遮挡区域、统一挂点与时间轴。武器类型选择通用动作，特殊武器提供动作覆盖；手部和武器使用同一动作节奏。相关设计见 [角色创建与外观动画](../角色系统/角色创建与外观动画.md)。

图片生成、逐帧预览、透明处理、部件拆分、绑定和 Godot 验收分别记录进度。仅完成源图时标记为设计参考，保持真实的完成边界。

当前动作阶段仅制作空手行走与跑步。攻击素材在攻击系统实现时制作，角色帧保留握持姿势，武器独立为可替换资产，通过挂点与共同时间轴配合；角色动作图中排除具体武器。

独立角色、行走、跑步及可替换部件素材应主动移除背景并交付真实透明 PNG，检查 Alpha、主体不透明度及深浅底边缘。人物设定稿与情境原画保留必要底色和场景。残留光晕、白边或杂色时登记未通过，继续修正后方可进入运行时资产。

动作具体尺寸、行列、切片与投影统一遵循 [俯视角色动作资产规范](俯视角色动作资产规范.md)。
